## 114-Q014

### Question

執行下列 C 語言程式，輸出的值為何？

```c
#include <stdio.h>
void func(int p)
{ p = p*p; }
int main()

  func(a);
```

- A. 0
- B. 3
- C. 9
- D. 編譯錯誤

### Potential novice blockers

- 不知道 `func(a)` 會把 `a` 的值複製到參數 `p`，不是把 `a` 本人交給函式。
- 容易把 `p = p*p` 的結果 9 誤以為會回寫到 `main` 的 `a`。
- 不熟 C 的區域變數：`p` 只存在於 `func` 裡，函式結束後就不再存在。
- 看到 `void` 可能誤判為編譯錯誤，其實 `void` 函式可以不回傳值。
- 不熟 `printf("%d\n", a)` 印的是 `main` 內目前的 `a`。

### Core terms

- pass by value
- 引數與參數
- 區域變數
- stack frame
- 指標
- `printf`

### Beginner explanation

既有 reviewed analysis 已符合新手標準：它清楚說明 `a` 與 `p` 是兩個不同變數，且把流程套回程式碼。合併時可保留內容，並可加入一張執行追蹤表讓非資工新手更穩。

C 語言一般函式呼叫採用 pass by value。這句話的意思是：呼叫 `func(a)` 時，系統把 `a` 當下的值 3 複製一份給 `func` 裡的參數 `p`。所以 `p` 一開始也是 3，但它不是 `main` 裡那個 `a`。

進入 `func` 後，`p = p*p` 只會讓 `func` 裡的 `p` 從 3 變成 9。函式結束後，`p` 這個區域變數消失；回到 `main` 時，`a` 從頭到尾都沒有被改過，仍然是 3。因此 `printf("%d\n", a)` 輸出 3。

如果要讓函式真的改到呼叫端的 `a`，C 通常要傳入位址或指標，而本題程式沒有這麼做。

### Teaching tables

建議需要表格。這是流程追蹤題，表格能顯示 `main` 的 `a` 與 `func` 的 `p` 是不同位置。

| 步驟 | `main` 中的 `a` | `func` 中的 `p` | 說明 |
| --- | --- | --- | --- |
| `int a=3;` | 3 | 尚未存在 | `a` 建立在 `main` 中 |
| `func(a);` 進入函式 | 3 | 3 | 把 `a` 的值複製給 `p` |
| `p = p*p;` | 3 | 9 | 只改到 `p`，不改 `a` |
| 回到 `main` 並 `printf` | 3 | 已消失 | 輸出 `a`，所以是 3 |

### Solving steps

1. `main` 先建立變數 `a`，值為 3。
2. 呼叫 `func(a)` 時，C 把 `a` 的值複製給參數 `p`。
3. `func` 內的 `p` 是區域變數，不是 `main` 裡的 `a`。
4. 執行 `p = p*p`，`p` 變成 9。
5. 函式結束後 `p` 消失，`a` 仍然是 3。
6. `printf("%d\n", a)` 印出 `a`，所以答案為 B。

### Option explanations

- A. 程式沒有把 `a` 設為 0，也沒有未初始化問題。
- B. `func` 修改的是參數 `p` 的複本，`main` 的 `a` 仍為 3。
- C. 9 是 `func` 內 `p` 的值，不會自動回寫到 `a`。
- D. 程式語法可編譯；`void` 函式不回傳值不是錯誤。

### Key takeaways

- C 函式參數預設是 pass by value，呼叫時會複製值。
- 參數 `p` 是函式內的區域變數，修改它不會自動修改呼叫端變數。
- 若要讓函式改到外部變數，通常要傳指標或位址。
- 程式追蹤題要分清楚每個變數在哪個作用域。

## 114-Q015

### Question

AVL 樹是二元搜尋樹(BST)的一種，其與一般 BST 的差別為何？

- A. 允許重複鍵值
- B. -1 ≤ 平衡因子 ≤ 1
- C. 支援多父節點
- D. 父節點與子節點值相差不超過 1

### Question type

### Source packet

### Potential novice blockers

- 不知道 BST 的基本排序規則：左小右大。
- 把 AVL 的平衡因子誤解成節點值的差，而不是子樹高度差。
- 不知道一般 BST 可能因插入順序退化成很長的鏈。
- 不理解「自平衡」是透過旋轉維持高度，而不是允許多父節點或改變鍵值。
- 對 `-1 ≤ 平衡因子 ≤ 1` 這種數學寫法不熟。

### Core terms

- AVL 樹
- BST
- 平衡因子
- 子樹高度
- 自平衡

### Beginner explanation

既有 reviewed analysis 已符合非資工新手標準：它先介紹 BST，再解釋 AVL 多出來的高度平衡限制。合併時可新增一張比較表，讓一般 BST 與 AVL 的差異更明顯。

BST 是二元搜尋樹，每個節點最多有左、右兩個子節點，並且通常遵守「左子樹鍵值較小、右子樹鍵值較大」的搜尋規則。一般 BST 如果插入順序很偏，例如一路遞增，樹可能變得像一條長鏈，查找效率會變差。

AVL 樹是在 BST 規則上加上自平衡條件。它會看每個節點左右子樹的高度差，這個差通常稱為平衡因子。AVL 要求平衡因子維持在 -1、0、1，也就是 -1 到 1 之間。若超出範圍，就透過旋轉調整樹形。

本題正確差異不是鍵值能不能重複，也不是父子節點的數值差，而是 AVL 要讓高度差維持在可接受範圍內。

### Teaching tables

建議需要表格。這是比較題，表格能把 BST 與 AVL 的共同點、差異與常見誤解並排。

| 項目 | 一般 BST | AVL 樹 | 本題判斷 |
| --- | --- | --- | --- |
| 基本排序 | 左小右大 | 保留左小右大 | 兩者共同點 |
| 平衡要求 | 不一定檢查高度差 | 平衡因子需在 -1 到 1 | AVL 的核心差異 |
| 失衡處理 | 可能退化成鏈 | 透過旋轉恢復平衡 | AVL 的自平衡特色 |
| 常見誤解 | 以為比較父子鍵值差 | 實際比較子樹高度差 | 排除 D |

### Solving steps

1. 先確認 AVL 仍然是 BST，所以它保留二元搜尋樹的排序規則。
2. 找 AVL 比一般 BST 多出的限制：每個節點要檢查左右子樹高度差。
3. 套用平衡因子規則：平衡因子通常為左子樹高度減右子樹高度。
4. AVL 要求平衡因子維持在 -1、0、1。
5. 若超出範圍，AVL 透過旋轉調整，而不是改變鍵值或允許多父節點。
6. 因此正確答案是 B。

### Option explanations

- A. 是否允許重複鍵值不是 AVL 與一般 BST 的核心差異。
- B. AVL 的核心限制是各節點平衡因子，也就是左右子樹高度差，介於 -1 到 1。
- C. AVL 仍然是樹結構，一個節點不會有多個父節點。
- D. AVL 比較的是子樹高度差，不是父節點與子節點的鍵值差。

### Key takeaways

- AVL 樹是自平衡 BST。
- 平衡因子看的是左右子樹高度差，不是鍵值大小差。
- AVL 通常要求平衡因子在 -1 到 1。
- 失衡時用旋轉恢復平衡，讓查找效率維持穩定。

### Beginner explanation

既有 reviewed analysis 已符合新手教學標準，而且已正確保留 `needs-review`。主代理合併時不應把本題硬改成無疑義 verified 題。

XOR 是一種邏輯閘，規則是「兩個輸入不同時輸出 1，兩個輸入相同時輸出 0」。例如 0 XOR 1 = 1，1 XOR 0 = 1，0 XOR 0 = 0，1 XOR 1 = 0。

在半加器中，只看兩個位元 A 和 B 相加時，不含進位的和位元就是 `A XOR B`。在全加器中又多了一個輸入進位 `Cin`，所以和位元變成 `A XOR B XOR Cin`。因此若題目只問加法器裡 XOR 最典型的直接用途，答案 D「計算每位的和，不含進位」符合題庫採答。

但本題必須保留疑義：二補數溢位檢測也常用最高位的 carry-in 與 carry-out 做 XOR，所以 B 不是完全無關。建議保留既有 answerNote 與 `needs-review`。

| --- | --- | --- | --- |
| 和位元 sum bit | 半加器 `A XOR B`；全加器 `A XOR B XOR Cin` | 是，對應 D | XOR 的典型直接用途 |
| 產生進位 | 半加器 `A AND B`；全加器常用 AND/OR 組合 | 否 | 不是單純 XOR |
| 溢位檢測 | 最高位 carry-in XOR carry-out | 有可辯性，對應 B | 二補數溢位可用 XOR 檢測 |
| 儲存符號位 | 儲存在位元/暫存器中 | 否 | XOR 不負責儲存 |

### Solving steps

1. 先回想 XOR 規則：輸入不同輸出 1，相同輸出 0。
2. 套用半加器：兩位相加時，不含進位的和是 `A XOR B`。
3. 套用全加器：多了 `Cin` 時，sum bit 是 `A XOR B XOR Cin`。
4. 檢查 A：進位產生通常由 AND/OR 類邏輯組合，不是單純 XOR。
5. 檢查 B：二補數 signed overflow 的確可能用 carry-in XOR carry-out，因此有可辯性。
6. 檢查 C：符號位是資料位元，不是 XOR 閘儲存出來的。
7. 依題庫採答，D 是最直接的標準用途；但保留 needs-review。

### Option explanations

- A. 產生進位要看輸入位元與輸入進位的組合，常用 AND/OR 邏輯，不是 XOR 的主要單獨功能。
- B. 二補數溢位可用最高位 carry-in 與 carry-out 做 XOR 檢測，因此有可辯性，但不是題庫採答。
- C. 符號位是二補數資料位元的一部分，儲存動作不由 XOR 閘負責。
- D. XOR 可計算每一位不含進位的和，這是半加器與全加器中的典型用途。

### Key takeaways

- XOR 表示「輸入不同」。
- 半加器 sum bit = `A XOR B`。
- 全加器 sum bit = `A XOR B XOR Cin`。
- carry generation 與 overflow detection 是不同功能。
- 本題採答 D，但 B 具有技術可辯性，需保留 `needs-review`。
