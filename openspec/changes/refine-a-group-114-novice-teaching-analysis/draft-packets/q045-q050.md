## 114-Q045

### Question

兩步驟驗證(Two-Step Verification)主要提升下列哪個面向？

- A. 可用性
- B. 完整性
- C. 不可否認性
- D. 機密性與認證強度

官方答案：D

### Question type

資安機制對安全屬性的對應題。重點是辨認兩步驟驗證屬於登入身分確認機制，並把它對應到認證強度與機密性，而不是把所有 CIA 或稽核屬性都套上去。

### Potential novice blockers

- 可能不知道 authentication 是確認「你是不是你」，不是授權或資料驗證。
- 可能把兩步驟驗證誤解成一定是多因子；本題只需要掌握密碼外再加第二步會提高登入門檻。
- 可能不熟 CIA：可用性、完整性、機密性的差異。
- 可能不知道不可否認性通常靠簽章、憑證、稽核紀錄等證據機制，不是單靠多一道登入步驟。

### Core terms

- Two-Step Verification：在密碼之外再加入第二個驗證步驟，例如 OTP、簡訊碼、推播確認或安全金鑰。
- authentication strength：認證強度，指攻擊者冒用身分登入的難度。
- second factor / second step：第二道驗證程序；在本題中用來提高帳號登入門檻。
- confidentiality：機密性，重點是未授權者不能讀取資料。
- integrity：完整性，重點是資料未被未授權竄改。
- non-repudiation：不可否認性，重點是事後能證明某操作確實由特定主體完成。

### Beginner explanation

兩步驟驗證要解決的問題是：只靠密碼時，只要密碼外洩，攻擊者就可能登入帳號。加入第二步後，登入者除了知道密碼，還必須完成另一個驗證程序，例如輸入一次性密碼、按下手機推播確認，或使用安全金鑰。

因此它最直接提升的是認證強度。認證強度提高後，未授權者比較難進入帳號，也就比較難讀取帳號裡的資料，所以可以保護機密性。這題的答案把「機密性」和「認證強度」放在一起，是合理的。

不要把兩步驟驗證硬套到所有安全屬性。它不是為了讓系統更容易使用，所以不是可用性；它也不是直接檢查資料有沒有被改，所以不是完整性；它更不是主要用來產生事後不可否認的證據。

### Teaching tables

表格決策：不需要新增 teachingTables。這題是單一資安機制對安全屬性的判斷，現有段落與 A-D 選項解釋已足以呈現新手所需的名詞、目的、規則與排除理由。若主代理想加表格，最多只適合作為安全屬性對照表，但會增加本題閱讀負擔。

### Solving steps

1. 先把 Two-Step Verification 定位成登入與身分確認機制。
2. 密碼之外再加第二步，代表攻擊者不能只靠偷到密碼就登入，因此直接提升認證強度。
3. 認證強度提升後，未授權登入變難，帳號內資料被讀取的機率下降，所以也保護機密性。
4. 排除 A：多一道驗證通常不會提高可用性，甚至可能讓登入更麻煩。
5. 排除 B：完整性是在談資料是否被未授權竄改，不是登入是否多一道驗證。
6. 排除 C：不可否認性通常需要簽章、憑證或稽核證據，不是兩步驟驗證的主要目標。
7. 因此答案選 D。

### Option explanations

- A：可用性是讓服務可被正常取得；兩步驟驗證主要不是讓系統更容易使用。
- B：完整性是保護資料不被未授權修改；兩步驟驗證不是直接驗證資料內容是否被改。
- C：不可否認性要能提供事後證據，常見機制是數位簽章、憑證或稽核紀錄。
- D：兩步驟驗證提高登入認證強度，降低未授權者讀取帳號資料的機會，符合題意。

### Key takeaways

- 兩步驟驗證的核心是加強登入身分確認。
- 認證強度提升會降低帳號被接管與資料外洩風險。
- 機密性、完整性、可用性、不可否認性要分開判斷，不要看到資安機制就全部套上去。

## 114-Q046

### Question

IDPS 偵測技術中，下列何者對「未知攻擊」一般表現最佳？

- A. 特徵偵測(Signature)
- B. 自動掃描(Auto Scanning)
- C. 狀態協定分析(Stateful Protocol)
- D. 異常行為(Anomaly)

官方答案：D

### Question type

資安偵測技術比較題。重點是比較 signature、stateful protocol analysis 與 anomaly detection 對已知攻擊、未知攻擊的適用性。

### Source packet

- originalStem：IDPS 偵測技術中，下列何者對「未知攻擊」一般表現最佳？
- options：A 特徵偵測(Signature)；B 自動掃描(Auto Scanning)；C 狀態協定分析(Stateful Protocol)；D 異常行為(Anomaly)
- acceptedAnswers：D
- answerVerification：verified
- answerNote：null
- raw tags：security, idps
- reviewed tags：anomaly-detection
- sourceRef：year 114, fileName 114.pdf, pageNumber 4, extractionStatus needs-review

### Potential novice blockers

- 可能不知道 IDPS 是入侵偵測與防禦系統，目的不是一般防毒或掃描工具。
- 可能把 signature 想成「很精準所以一定最好」，忽略它需要已知攻擊樣式。
- 可能不知道 baseline 是正常行為基準。
- 可能不知道 anomaly detection 的優點是可找偏離正常的未知行為，缺點是誤報較多。
- 可能不理解 stateful protocol analysis 是用協定規則檢查流程，不等於對未知攻擊最佳。

### Core terms

- IDPS：Intrusion Detection and Prevention System，用來偵測或阻擋可疑入侵行為。
- signature detection：特徵偵測，比對已知攻擊樣式或規則。
- anomaly detection：異常行為偵測，先建立正常基準，再找偏離正常的事件。
- baseline：正常行為基準，例如平常流量、登入時間、指令頻率或協定使用型態。
- false positive：誤報，把正常但少見的行為判成異常。
- stateful protocol analysis：依協定狀態與流程規則檢查行為是否合理。

### Beginner explanation

IDPS 要解決的問題是：系統或網路裡可能出現攻擊行為，需要被偵測甚至阻擋。不同偵測技術的差別，在於它們用什麼依據判斷「這像不像攻擊」。

特徵偵測像拿事件去比對已知黑名單：只要符合某個已知攻擊特徵就告警。它對已知攻擊通常很有效，但如果攻擊是新的，還沒有規則可以比對，就會比較吃虧。

異常行為偵測則先學會什麼叫正常，例如平常的登入時間、流量大小、指令頻率，再抓偏離正常的行為。未知攻擊雖然沒有既有特徵，但它可能造成異常活動，所以 anomaly detection 一般較適合未知攻擊。不過它不是完美方法，因為正常但少見的行為也可能被誤判。

### Teaching tables

表格決策：建議需要 teachingTables。這題是偵測技術比較題，表格能讓非資工新手快速看出各技術的判斷依據、適合情境與陷阱。

建議表格：

| 技術 | 判斷依據 | 對未知攻擊的表現 | 常見陷阱 |
| --- | --- | --- | --- |
| Signature | 已知攻擊特徵或規則 | 較弱，因為未知攻擊未必有規則 | 精準不代表能抓未知攻擊 |
| Stateful Protocol | 協定狀態與流程是否合理 | 中等，受限於既定協定規則 | 不是所有未知攻擊都會違反協定流程 |
| Anomaly | 正常 baseline 與偏離程度 | 較佳，能抓偏離正常的新行為 | 可能 false positive 較高 |

### Solving steps

1. 先看題目關鍵字：「未知攻擊」。
2. 未知攻擊代表沒有現成攻擊特徵可比對，所以 A signature detection 先被削弱。
3. B 自動掃描不是 IDPS 對未知攻擊最具代表性的偵測分類，且不能直接等同於能發現未知攻擊。
4. C stateful protocol analysis 可檢查協定流程是否合理，但仍依賴既定協定規則。
5. D anomaly detection 依正常 baseline 找偏離行為，較有機會抓到未知攻擊或新變種。
6. 因此答案選 D，同時補充它的限制是誤報可能較多。

### Option explanations

- A：特徵偵測適合已知攻擊；未知攻擊還沒有 signature 時，偵測能力會下降。
- B：自動掃描偏向掃描或檢查活動，不是本題所問最典型的未知攻擊偵測技術。
- C：狀態協定分析可檢查協定流程是否違規，但通常仍受限於已知協定規則。
- D：異常行為偵測先建立正常基準，再抓偏離基準的活動，較適合發現未知攻擊。

### Key takeaways

- 題目問未知攻擊時，優先想到 anomaly detection。
- Signature 適合已知攻擊，因為它需要已知特徵。
- Anomaly detection 的代價是 false positive 可能較高。
- Stateful protocol analysis 是協定流程檢查，不等於對未知攻擊一定最佳。

## 114-Q047

### Question

下列何者非屬 Session Hijacking 常見取得會話的手段？

- A. MITM
- B. Sniffing
- C. UDP 檔案傳輸
- D. XSS

官方答案：C

### Question type

資安攻擊手法排除題。題目問「非屬」，所以要辨認哪些選項能取得或濫用 session token / cookie，並排除只是一般傳輸描述的選項。

### Source packet

- originalStem：下列何者非屬 Session Hijacking 常見取得會話的手段？
- options：A MITM；B Sniffing；C UDP 檔案傳輸；D XSS
- acceptedAnswers：C
- answerVerification：verified
- answerNote：null
- raw tags：security, session-hijacking
- reviewed tags：web-security
- sourceRef：year 114, fileName 114.pdf, pageNumber 4, extractionStatus needs-review

### Potential novice blockers

- 可能不知道 session 是登入後網站用來記住使用者狀態的機制。
- 可能不知道 session token / cookie 可以代表已登入身分。
- MITM、Sniffing、XSS 都是縮寫或英文術語，非資工新手容易只靠印象猜。
- 題目問「非屬」，需要反向找出不是常見取得會話手段的選項。
- 可能看到 UDP 是網路協定，就誤以為它自然也是 session hijacking 手法。

### Core terms

- Session Hijacking：會話劫持，攻擊者取得或濫用受害者的登入會話。
- session token：伺服器用來識別已登入使用者的一串值。
- cookie：瀏覽器保存網站資料的機制，常用來帶 session token。
- MITM：中間人攻擊，攻擊者插在通訊雙方之間攔截或操弄資料。
- Sniffing：竊聽封包，嘗試讀取網路傳輸中的資訊。
- XSS：跨站腳本攻擊，讓惡意腳本在使用者瀏覽器執行。

### Beginner explanation

Session Hijacking 要解決的判斷重點是：攻擊者是否能取得或濫用代表登入狀態的 session token 或 cookie。使用者登入後，網站不會每次都重新問密碼，而是用 session token 判斷「這個請求屬於已登入使用者」。攻擊者若拿到 token，就可能冒用使用者。

MITM 可能攔截或操弄通訊；Sniffing 可能在未加密或保護不足時竊聽封包；XSS 可能讓惡意腳本在受害者瀏覽器中偷 cookie 或直接替使用者發請求。這三者都可能和 session hijacking 連上關係。

UDP 檔案傳輸只是描述用 UDP 傳資料，它本身不是典型取得或濫用 session token 的攻擊手法。因此題目問「非屬」時，答案是 C。

### Teaching tables

表格決策：不必強制新增 teachingTables。這題雖然有分類性質，但現有 beginnerExplanation、solvingSteps 與 optionExplanations 已逐一把每個選項連回 session token / cookie。若主代理想降低縮寫負擔，可加入簡短分類表；但不是必要表格題。

可選表格：

| 選項 | 是否常見相關手段 | 和 session 的關係 |
| --- | --- | --- |
| MITM | 是 | 可攔截或操弄通訊，取得會話資訊 |
| Sniffing | 是 | 可竊聽未受保護封包中的 token |
| UDP 檔案傳輸 | 否 | 只是傳輸方式描述，不是典型竊取 session 的手法 |
| XSS | 是 | 可偷 cookie 或用受害者 session 發請求 |

### Solving steps

1. 先確認 Session Hijacking 的目標是取得或冒用 session token、cookie 或會話識別資訊。
2. 檢查 A MITM：中間人攻擊可能攔截通訊並取得會話資訊，屬於常見手段。
3. 檢查 B Sniffing：竊聽封包在未加密或保護不足時可能取得 token，屬於常見手段。
4. 檢查 D XSS：惡意腳本可能偷 cookie 或直接用受害者 session 操作，屬於常見手段。
5. 檢查 C UDP 檔案傳輸：它不是典型取得會話的攻擊方法，因此是非屬選項。
6. 因此答案選 C。

### Option explanations

- A：MITM 可攔截或篡改通訊，若保護不足可能取得 session token。
- B：Sniffing 可竊聽網路封包，未加密或設定不良時可能暴露會話資訊。
- C：UDP 檔案傳輸不是典型的 session token 竊取或冒用方法，因此是本題的非屬選項。
- D：XSS 可在使用者瀏覽器中執行惡意腳本，常被用來偷 cookie 或操作既有 session。

### Key takeaways

- Session Hijacking 的核心是 session token 或 cookie 被取得或濫用。
- MITM、Sniffing、XSS 都能和會話資訊外洩或濫用有關。
- 網路協定或傳輸方式名稱本身不等於攻擊手法。
- 看到「非屬」題，要找出不符合核心目標的選項。

## 114-Q048

- C. WAF 不做代理
- D. WAF 不支援 SSL

官方答案：B

### Question type

網路安全設備比較題。重點是比較 WAF 與傳統封包過濾式防火牆觀察的層級與內容。

- answerNote：null
- raw tags：security, firewall
- reviewed tags：waf, application-layer

### Potential novice blockers

- 可能不知道 WAF 是 Web Application Firewall，不是一般防火牆的同義詞。
- 可能不知道封包過濾式防火牆主要看 IP、port、protocol 等封包欄位。
- 可能不了解 application layer 代表能檢查 HTTP request、URL、header、cookie、body 或參數。
- 可能被第 2 層、代理、SSL 這些字眼帶走，忽略題目問「主要差異」。
- 可能不知道 SQLi、XSS 是 Web 應用層攻擊範例。

### Core terms

- WAF：Web Application Firewall，針對 Web 應用流量做檢查與防護。
- packet-filtering firewall：封包過濾式防火牆，常依 IP、port、protocol 等條件放行或阻擋。
- application layer：應用層，這裡主要指 HTTP/HTTPS 請求內容與命令語意。
- HTTP：Web 應用常用協定，包含 URL、header、cookie、body、參數等資訊。
- SQLi / XSS：常見 Web 應用攻擊，WAF 通常會嘗試偵測或阻擋。

### Beginner explanation

傳統封包過濾式防火牆像門口守衛，常看封包外部資訊：來源 IP、目的 IP、port、protocol、連線狀態。這些資訊可以判斷哪些網路連線可以通過，但不一定理解 Web 表單裡的參數或 HTTP request 的語意。

WAF 的重點是 Web 應用層。它會看 HTTP/HTTPS 的 URL、header、cookie、body、表單參數與命令模式，嘗試找出 SQL Injection、XSS 這類 Web 應用攻擊。

所以本題主要差異不是 WAF 有沒有做代理，也不是能不能支援 SSL，而是 WAF 會檢視與過濾應用層內容/命令。A、C、D 都太絕對或方向錯誤。

### Teaching tables

表格決策：建議需要 teachingTables。這題是明確比較 WAF 與封包過濾式防火牆的題型，表格能直接呈現觀察層級與判斷依據。

建議表格：

| 項目 | 傳統封包過濾式防火牆 | WAF |
| --- | --- | --- |
| 主要觀察內容 | IP、port、protocol、連線狀態 | URL、header、cookie、body、參數、HTTP 命令模式 |
| 主要層級 | 較偏網路層/傳輸層欄位 | 應用層，特別是 Web/HTTP |
| 常見防護目標 | 控制哪些連線可通過 | 阻擋 SQLi、XSS 等 Web 應用攻擊 |
| 本題判斷 | 不能看懂完整 Web 語意 | 能檢視與過濾應用層內容/命令 |

1. 先辨認 WAF 是 Web Application Firewall，重點在 Web 應用層保護。

### Question

- A. ICMP
- B. IGMP

### Question type

TCP/IP 分層與協定分類題。題目問「非屬」網路層，所以要把各協定依功能放到網路層或傳輸層。

### Source packet

- originalStem：下列何者非屬 TCP/IP 網路中之網路層通訊協定？
- options：A ICMP；B IGMP；C OSPF；D UDP
- acceptedAnswers：D

- answerNote：null

- reviewed tags：udp, network-layer

### Potential novice blockers

- 可能把「網路通訊協定」全部誤認成「網路層協定」。
- 可能不熟 TCP/IP 分層：Internet layer 與 Transport layer 的責任不同。
- 可能知道 UDP 是網路常見協定，卻不知道它與 TCP 同屬傳輸層。
- 可能不熟 ICMP、IGMP、OSPF 的用途。
- 題目問「非屬」，需要找出不在網路層的協定。

### Core terms

- Internet layer：TCP/IP 中負責 IP 定址、路由與網路控制訊息的層級。
- transport layer：傳輸層，處理端到端資料傳輸、port、可靠性或無連線傳送。
- ICMP：常用於錯誤回報與診斷控制訊息，例如 ping 相關訊息。
- IGMP：管理 IPv4 multicast 群組。
- OSPF：動態路由協定，用來交換路由資訊。
- UDP：傳輸層協定，提供無連線資料報服務，會使用 port。

### Beginner explanation

TCP/IP 分層題要先問：「這個協定主要負責什麼工作？」Internet layer 網路層負責跨網路的定址、路由與控制訊息，像是在回答封包要怎麼從一個網路走到另一個網路。

Transport layer 傳輸層則處理應用程式之間的資料傳送，會用 port 區分不同應用，常見代表是 TCP 和 UDP。UDP 雖然是網路通訊常見協定，但它不屬於網路層，而是傳輸層。

ICMP 用於錯誤回報與診斷，IGMP 管理 multicast 群組，OSPF 交換路由資訊，這些都和網路層的控制或路由功能有關。因此本題問「非屬」網路層時，答案是 D。

| IGMP | 網路層相關控制 | IPv4 multicast 群組管理 | 屬於網路層相關 |
| OSPF | 網路層路由控制 | 交換路由資訊、決定路徑 | 屬於網路層相關 |

### Solving steps

1. 題目要找「非屬」TCP/IP 網路層的協定。

3. 檢查 A ICMP：用於錯誤回報與診斷，屬於網路層相關控制。
