## 114-Q005

### Question

在使用偶校驗的漢明碼(Hamming Code)中，已知原始資料為 1011，發送端應傳送的完整資料(原始資料+校驗位)為何？

### Question type

錯誤更正碼計算題。題目要求套用標準 Hamming(7,4) 位置配置與偶校驗規則。

### Source packet

- Original stem: 在使用偶校驗的漢明碼(Hamming Code)中，已知原始資料為 1011，發送端應傳送的完整資料(原始資料+校驗位)為何？
- Options: A. 0011011; B. 0110011; C. 0110110; D. 1110011
- Official answer: B
- answerVerification: verified
- answerNote: 採標準 Hamming(7,4) 位置配置：第 1、2、4 位為校驗位，第 3、5、6、7 位放入資料 1011。
- Tags: computer-principles, error-correction, hamming-code
- sourceRef: year 114, fileName 114.pdf, pageNumber 1, extractionStatus needs-review

### Potential novice blockers

- 不知道 Hamming(7,4) 代表 7 個傳送位元、4 個資料位、3 個校驗位。
- 容易把位元位置從 0 開始編號，但本題標準配置使用第 1 到第 7 位。
- 不知道校驗位為何放在 1、2、4 這些 2 的冪次位置。
- 偶校驗與奇校驗容易混淆。
- 需要同時保存資料位順序與校驗位檢查組，對新手負擔較高。

### Core terms

- Hamming(7,4): 4 個資料位加上 3 個校驗位，形成 7 位碼字。
- 偶校驗: 每個檢查組內的 1 總數必須是偶數。
- 校驗位位置: 第 1、2、4 位是 p1、p2、p4。
- 資料位位置: 第 3、5、6、7 位依序放入原始資料 1011。
- 檢查組: 每個校驗位負責一組位置，例如 p1 檢查 1、3、5、7。

### Beginner explanation

既有 reviewed analysis 已達非資工新手教學標準：它先定義 Hamming(7,4)、偶校驗與校驗位位置，再把資料 1011 放到第 3、5、6、7 位，最後逐一算出 p1、p2、p4。

可再補強的地方是用表格把「位置、角色、值」與「校驗位檢查組」攤開。這題不是只背答案，而是要知道校驗位會被選成讓檢查組的 1 總數變偶數。把資料放入後得到 `_ _ 1 _ 0 1 1`，再算 p1=0、p2=1、p4=0，所以完整碼字是 `0110011`。

### Teaching tables

表格決策：建議需要表格。這題屬於流程與公式參照型內容，位置配置若只用段落說明，新手容易錯位。

建議表格 1：

| 位置 | 角色 | 放入值 | 說明 |
| --- | --- | --- | --- |
| 1 | p1 | 0 | 讓位置 1、3、5、7 的 1 總數為偶數 |
| 2 | p2 | 1 | 讓位置 2、3、6、7 的 1 總數為偶數 |
| 3 | d1 | 1 | 原始資料 1011 的第 1 位 |
| 4 | p4 | 0 | 讓位置 4、5、6、7 的 1 總數為偶數 |
| 5 | d2 | 0 | 原始資料 1011 的第 2 位 |
| 6 | d3 | 1 | 原始資料 1011 的第 3 位 |
| 7 | d4 | 1 | 原始資料 1011 的第 4 位 |

建議表格 2：

| 校驗位 | 檢查位置 | 已知資料位的 1 個數 | 偶校驗決定 |
| --- | --- | --- | --- |
| p1 | 1、3、5、7 | 位置 3、5、7 為 1、0、1，共 2 個 1 | 已是偶數，p1=0 |
| p2 | 2、3、6、7 | 位置 3、6、7 為 1、1、1，共 3 個 1 | 需補 1 變偶數，p2=1 |
| p4 | 4、5、6、7 | 位置 5、6、7 為 0、1、1，共 2 個 1 | 已是偶數，p4=0 |

### Solving steps

1. 確認使用 Hamming(7,4)：第 1、2、4 位是校驗位，第 3、5、6、7 位是資料位。
2. 將原始資料 1011 依序放入資料位，得到 `_ _ 1 _ 0 1 1`。
3. 計算 p1 檢查組 1、3、5、7；已知 1、0、1 有 2 個 1，因此 p1=0。
4. 計算 p2 檢查組 2、3、6、7；已知 1、1、1 有 3 個 1，因此 p2=1。
5. 計算 p4 檢查組 4、5、6、7；已知 0、1、1 有 2 個 1，因此 p4=0。
6. 從第 1 位到第 7 位寫出 p1 p2 d1 p4 d2 d3 d4，得到 0 1 1 0 0 1 1。
7. 完整碼字為 `0110011`，對應選項 B。

### Option explanations

- A: `0011011` 的 p2 與 p4 會破壞偶校驗，不符合標準 Hamming(7,4) 配置。
- B: `0110011` 保留資料位 1011，且 p1、p2、p4 都讓檢查組為偶數，正確。
- C: `0110110` 從第 3、5、6、7 位讀回資料會變成 1110，不是題目給的 1011。
- D: `1110011` 將 p1 設為 1，會使 p1 檢查組變成奇數個 1，像是把偶校驗誤當奇校驗。

### Key takeaways

- Hamming(7,4) 的校驗位在第 1、2、4 位。
- 資料 1011 要依序放到第 3、5、6、7 位。
- 偶校驗的目標是讓每個檢查組中的 1 總數為偶數。
- 新手最常錯在從 0 開始編號、資料位放錯、或奇偶校驗混用。

### Answer note changes

建議保留既有 answerNote。若後續合併新增 teachingTables，可不改變官方答案，只補充「本題採 1-based Hamming(7,4) 標準位置配置」的可讀性。

### Reviewer concerns

- Technical Reviewer: pass。計算結果與既有 answerNote 一致。
- Novice Reviewer: pass。既有說明已有前置名詞、規則與套用步驟；表格可進一步降低錯位風險。
- Table Reviewer: fixed in draft。建議新增位置表與檢查組表，屬於流程與公式參照型表格，符合 teachingTables 使用範圍。
- needs-review: 無答案疑義，但合併時需保留 Hamming(7,4) 標準配置假設。

## 114-Q006

### Question

下列何者為交易(Transaction)的 ACID 特性？

### Question type

資料庫概念辨識題。題目要求辨認交易 ACID 四個字母的標準展開。

### Source packet

- Original stem: 下列何者為交易(Transaction)的 ACID 特性？
- Options: A. Availability, Consistency, Integrity, Dependability; B. Atomicity, Concurrency, Integrity, Durability; C. Availability, Concurrency, Isolation, Dependability; D. Atomicity, Consistency, Isolation, Durability
- Official answer: D
- answerVerification: verified
- answerNote: null
- Tags: database, transaction, acid
- sourceRef: year 114, fileName 114.pdf, pageNumber 1, extractionStatus needs-review

### Potential novice blockers

- ACID 是英文縮寫，非資工新手可能只靠字母猜。
- Availability、Concurrency、Integrity、Dependability 都是合理技術詞，容易被混入干擾。
- Consistency 在 ACID 中是資料規則一致，不是一般口語「穩定」。
- Isolation 不是「並行能力」，而是並行交易之間的隔離。

### Core terms

- Transaction: 一組必須被當成整體處理的資料庫操作。
- Atomicity: 原子性，全做或全不做。
- Consistency: 一致性，交易前後都符合資料庫規則與約束。
- Isolation: 隔離性，並行交易不應看到彼此不該暴露的中間狀態。
- Durability: 持久性，提交後資料應保存，即使發生故障也不應輕易消失。

### Beginner explanation

既有 reviewed analysis 已達非資工新手教學標準：它先說明 transaction 是一組整體操作，再逐一解釋 Atomicity、Consistency、Isolation、Durability，並指出干擾字 Availability、Concurrency、Integrity、Dependability 為何不是 ACID 的標準字母。

這題的核心不是背 D，而是知道 ACID 用來描述交易可靠性。轉帳、訂單或庫存更新不能只做一半，也不能讓資料違反規則；多個交易同時跑時要互相隔離，交易提交後也要能保存。

### Teaching tables

表格決策：建議需要表格。這題是分類與比較型內容，用表格列出 ACID 與干擾詞可降低英文縮寫負擔。

建議表格：

| 字母 | 正確詞 | 中文概念 | 常見干擾 |
| --- | --- | --- | --- |
| A | Atomicity | 全做或全不做 | Availability 是可用性，不是交易 ACID 的 A |
| C | Consistency | 交易前後符合資料規則 | Concurrency 是並行能力，Integrity 是完整性概念 |
| I | Isolation | 並行交易彼此隔離 | Integrity 不是 ACID 的 I |
| D | Durability | 提交後資料持久保存 | Dependability 是可靠性泛稱，不是 ACID 的 D |

### Solving steps

1. 先確認題目問的是資料庫交易的 ACID，而不是一般系統可靠性。
2. 展開 A 為 Atomicity，排除 Availability。
3. 展開 C 為 Consistency，排除 Concurrency 或 Integrity。
4. 展開 I 為 Isolation，排除 Integrity。
5. 展開 D 為 Durability，排除 Dependability。
6. 逐項比對四個選項，只有 D 同時列出 Atomicity, Consistency, Isolation, Durability。

### Option explanations

- A: Availability 與 Dependability 不是 ACID；Integrity 也不是 ACID 的 C。
- B: Atomicity 和 Durability 正確，但 Concurrency 與 Integrity 不是 ACID 的 C 和 I。
- C: Isolation 正確，但 Availability、Concurrency、Dependability 都不是 ACID 的標準展開。
- D: Atomicity, Consistency, Isolation, Durability 完整對應 ACID，正確。

### Key takeaways

- ACID 描述交易處理可靠性，不是一般系統可用性清單。
- Atomicity 是全做或全不做。
- Consistency 是交易前後符合資料規則。
- Isolation 是並行交易互相隔離，不等於 Concurrency。
- Durability 是提交後資料持久保存。

## 114-Q007

### Question

在優先權排程中，為避免飢餓(Starving)發生，應採用下列何種策略？

### Question type

作業系統排程策略題。題目要求辨認優先權排程中避免 starvation 的標準策略。

### Source packet

- Original stem: 在優先權排程中，為避免飢餓(Starving)發生，應採用下列何種策略？
- Options: A. 老化(Aging)機制; B. 增加 CPU 核心數; C. 降低時間片(Time Quantum)長度; D. 強制終止高優先級進程
- Official answer: A
- answerVerification: verified
- answerNote: null
- Tags: operating-system, scheduling, starvation
- sourceRef: year 114, fileName 114.pdf, pageNumber 1, extractionStatus needs-review

### Potential novice blockers

- 容易把 starvation 與 deadlock、CPU 不夠快混為一談。
- 不理解優先權排程如何讓低優先權行程長期被延後。
- Aging 的中文「老化」容易被誤解成硬體老化，而非等待越久優先權越高。
- Time quantum 屬於輪轉排程概念，容易被錯套到優先權飢餓。

### Core terms

- 優先權排程: 排程器優先讓高優先權行程取得 CPU。
- Starvation: 行程長期等不到資源，常見於低優先權行程一直被高優先權行程插隊。
- Aging: 等待越久，逐步提高該行程的優先權。
- Time quantum: 輪轉排程中的時間片長度，不是解決優先權飢餓的核心。

### Beginner explanation

既有 reviewed analysis 已達非資工新手教學標準：它先說明優先權排程的目的與副作用，再定義 starvation，最後說明 Aging 透過等待時間補償低優先權行程。

這題要抓住問題來源：不是 CPU 核心太少，也不是每個行程跑太久，而是低優先權行程一直被更高優先權工作壓住。Aging 會讓等待越久的行程優先權逐步提升，因此能避免永遠排不到。

### Teaching tables

表格決策：不建議新增 teachingTables。這題是單一策略辨識，既有段落與選項解析已能清楚建立目的、規則與干擾差異。若後續審查要求表格，可只做簡短「策略對照表」，但目前不是必要。

### Solving steps

1. 讀出題目場景：優先權排程中要避免低優先權行程長期等待。
2. 把這種長期得不到 CPU 的狀態對應到 starvation。
3. 套用 Aging 規則：等待時間越久，優先權越高。
4. 檢查 A：老化機制直接調整等待行程的優先權，符合需求。
5. 檢查 B：增加 CPU 核心數可能提升吞吐量，但不保證公平性。
6. 檢查 C：降低 time quantum 主要影響輪轉排程，不是本題核心。
7. 檢查 D：強制終止高優先級進程會破壞系統語意，不是標準策略。

### Option explanations

- A: Aging 會提高等待過久行程的優先權，能直接避免 starvation，正確。
- B: 增加 CPU 核心數可能讓系統變快，但無法保證低優先權行程不再被插隊。
- C: Time quantum 是輪轉排程常見參數，與優先權飢餓的標準解法不同。
- D: 強制終止高優先級進程副作用大，也不是作業系統排程用來避免 starvation 的正常策略。

### Key takeaways

- Starvation 是行程長期得不到資源，不等於單純效能不足。
- Aging 是等待越久優先權越高，用時間補償低優先權。
- 解決公平性問題通常要改排程規則，而不只是增加硬體。
- Time quantum 與 Aging 屬於不同排程觀念，考題常用來互相干擾。

## 114-Q008

### Question

給定一棵有 6 個節點的二元樹，前序走訪(Preorder)為 A,B,D,E,C,F，中序走訪(Inorder)為 D,B,E,A,C,F，其後序走訪(Postorder)為下列何者？

### Question type

資料結構推導題。題目要求利用 preorder 與 inorder 重建二元樹，再輸出 postorder。

### Source packet

- Original stem: 給定一棵有 6 個節點的二元樹，前序走訪(Preorder)為 A,B,D,E,C,F，中序走訪(Inorder)為 D,B,E,A,C,F，其後序走訪(Postorder)為下列何者？
- Options: A. A,B,D,E,C,F; B. D,B,E,F,C,A; C. D,E,B,F,C,A; D. F,C,A,E,B,D
- Official answer: C
- answerVerification: verified
- answerNote: null
- Tags: data-structure, tree-traversal, binary-tree
- sourceRef: year 114, fileName 114.pdf, pageNumber 1, extractionStatus needs-review

### Potential novice blockers

- Preorder、Inorder、Postorder 三種名稱容易只背英文而忘記順序。
- 不知道 preorder 第一個元素是整棵樹根。
- 不知道 inorder 可用根節點切分左右子樹。
- 遞迴重建對非資工新手抽象，容易直接拿輸入序列當答案。
- 後序最後才輸出根，這點常被忽略。

### Core terms

- Preorder: 根、左、右。
- Inorder: 左、根、右。
- Postorder: 左、右、根。
- 根節點: 子樹的起點，在 preorder 中會先出現。
- 遞迴重建: 對左右子樹重複「找根、切 inorder」的程序。

### Beginner explanation

既有 reviewed analysis 已達非資工新手教學標準：它先定義三種走訪順序，再示範用前序第一個 A 作根，於中序序列切出左子樹 D,B,E 與右子樹 C,F，最後套用後序規則。

這題可再用表格補強每一輪重建。新手不一定能在腦中保留多個序列切片，因此表格能讓「哪一段是左子樹、哪一段是右子樹、最後輸出什麼」更穩。

### Teaching tables

表格決策：建議需要表格。這題是流程推導與遞迴重建，表格可支援新手逐步追蹤。

建議表格：

| 子樹範圍 | Preorder 判斷根 | Inorder 切分 | Postorder 輸出 |
| --- | --- | --- | --- |
| 整棵樹 | A | 左 D,B,E；右 C,F | 左子樹、右子樹、A |
| A 的左子樹 | B | 左 D；右 E | D,E,B |
| A 的右子樹 | C | 左空；右 F | F,C |
| 合併 | - | - | D,E,B,F,C,A |

### Solving steps

1. Preorder 第一個元素是 A，所以 A 是整棵樹根。
2. 在 Inorder `D,B,E,A,C,F` 中找到 A，A 左邊 `D,B,E` 是左子樹，右邊 `C,F` 是右子樹。
3. 左子樹的 Preorder 是 `B,D,E`，所以 B 是左子樹根。
4. 在左子樹 Inorder `D,B,E` 中，D 在 B 左邊，E 在 B 右邊，因此左子樹後序是 `D,E,B`。
5. 右子樹的 Preorder 是 `C,F`，所以 C 是右子樹根；Inorder `C,F` 表示 F 在 C 右邊。
6. 右子樹後序是 `F,C`。
7. 整棵樹 Postorder 為左子樹、右子樹、根，所以是 `D,E,B,F,C,A`。

### Option explanations

- A: `A,B,D,E,C,F` 是題目給的 preorder，不是 postorder；後序中根 A 應在最後。
- B: `D,B,E,F,C,A` 把左子樹根 B 放太早，違反後序「左、右、根」。
- C: `D,E,B,F,C,A` 符合左子樹後序、右子樹後序、最後根 A，正確。
- D: `F,C,A,E,B,D` 把 A 放在中間，違反整棵樹根最後輸出的規則。

### Key takeaways

- Preorder 第一個是根。
- Inorder 可用根切成左子樹與右子樹。
- Postorder 是左、右、根，整棵樹根會出現在最後。
- 樹走訪推導題要逐步重建，不能直接把題目給的序列改名當答案。

### Answer note changes

不需新增 answerNote。既有 `null` 可保留。

### Reviewer concerns

- Technical Reviewer: pass。重建樹與後序結果正確。
- Novice Reviewer: pass。既有解釋已具備規則與套用；建議用表格降低遞迴負擔。
- Table Reviewer: fixed in draft。建議新增重建流程表，屬流程型表格。
- needs-review: 無。

### Question
