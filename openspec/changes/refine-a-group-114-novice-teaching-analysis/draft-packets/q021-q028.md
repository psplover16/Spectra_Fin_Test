## 114-Q021

### Question
下列何者為 CPU 工作排程中使用 FCFS 演算法的優點？

### Question type
作業系統排程概念題；判斷 FCFS 的核心規則、優點與常見缺點。

### Source packet
- 題號：114-Q021
- Topic：FCFS 排程
- 官方答案：A
- 選項：
  - A：簡單易懂、容易實作且公平
  - B：平均等待時間最短
  - C：適合互動式系統
  - D：CPU 使用效率高
- sourceRef：`114.pdf` page 3，`extractionStatus: needs-review`
- Reviewed baseline：既有 reviewed analysis 已標示 `answerVerification: verified`、`answerNote: null`，並已有 FCFS、FIFO、convoy effect 的新手導向說明。

### Potential novice blockers
- 不知道 FCFS 是 First-Come, First-Served，也不知道它和 FIFO 佇列的關係。
- 容易把「公平」理解成「效能一定最好」。
- 不知道平均等待時間最短通常不是 FCFS 的保證。
- 不熟悉互動式系統為什麼重視快速回應與搶佔。
- 沒聽過 convoy effect，無法理解長工作排前面會拖慢後面短工作的問題。

### Core terms
- FCFS：First-Come, First-Served，先到先服務。
- FIFO：First-In, First-Out，先進先出佇列規則。
- 就緒佇列：等待 CPU 執行的工作隊伍。
- 平均等待時間：工作從等待到取得 CPU 之間的平均等待長度。
- 互動式系統：使用者期待快速回應的系統。
- Convoy effect：長工作排在前面，讓後面短工作一起被卡住的現象。

### Beginner explanation
既有 reviewed analysis 已符合非資工新手教學標準。它先把 FCFS 翻成「先到先服務」，再用 FIFO 排隊比喻解釋誰先進入就緒佇列、誰就先拿到 CPU。這能讓沒有作業系統背景的讀者先理解規則，再判斷選項。

本題要分清楚「規則簡單、公平」和「效能最佳」不是同一件事。FCFS 的優點是直覺、容易實作、先來先服務；但它不會因為工作比較短、互動需求比較高，就讓某個工作插隊。因此它不能保證平均等待時間最短，也不一定適合互動式系統。

### Teaching tables
不需要。這題是單一排程規則的優缺點判斷，既有段落與步驟已足夠。若主代理後續想補表格，最多只需一張「FCFS 優點 / 非保證項目」二欄小表，但不是必要表格。

### Solving steps
1. 先把 FCFS 讀成 First-Come, First-Served，也就是依到達順序服務。
2. 確認題目問「優點」，不是問所有排程演算法中最有效率的策略。
3. 將 FCFS 的主要優點對上選項：簡單、容易實作、先來先服務的公平性。
4. 排除平均等待時間最短，因為短工作可能被長工作擋住。
5. 排除適合互動式系統，因為 FCFS 不會主動搶佔長工作。
6. 排除 CPU 使用效率高，因為 convoy effect 可能讓整體體感變差。
7. 因此選 A。

### Option explanations
- A：正確。FCFS 依到達順序服務，規則直覺，實作簡單，也具有先來先服務的公平性。
- B：錯誤。平均等待時間最短不是 FCFS 的保證，短工作若排在長工作後面會等很久。
- C：錯誤。互動式系統通常需要快速回應，較常搭配 Round Robin 或搶佔式排程。
- D：錯誤。FCFS 可能出現 convoy effect，不能說 CPU 使用效率必然高。

### Key takeaways
- FCFS 的核心是 FIFO 排隊。
- FCFS 的主要優點是簡單、容易實作、規則公平。
- FCFS 不保證平均等待時間最短，也不特別適合互動式系統。
- 看到 FCFS 題目，要小心把「公平」誤認成「效能最佳」。

### Answer note changes
不需要變更。既有 `answerNote: null` 合理，答案 A 沒有明顯疑義。

### Reviewer concerns
- Technical Reviewer：pass。FCFS 優缺點與 convoy effect 說明正確。
- Novice Reviewer：pass。已先解釋 FCFS/FIFO，再套回選項。
- Table Reviewer：pass。無表格也合理，不需強制新增 teachingTables。

## 114-Q022

### Question
採用全彩(True Color)模式處理數位影像時，R(0)、G(0)、B(0)所產生的顏色為何？

### Question type
多媒體與色彩模型概念題；判斷 RGB 加色模型中的三通道數值。

### Source packet
- 題號：114-Q022
- Topic：True Color RGB
- 官方答案：D
- 選項：
  - A：透明
  - B：白色
  - C：灰色
  - D：黑色
- sourceRef：`114.pdf` page 3，`extractionStatus: needs-review`
- Reviewed baseline：既有 reviewed analysis 已標示 `answerVerification: verified`、`answerNote: null`，並清楚區分 RGB 與 alpha channel。

### Potential novice blockers
- 不知道 RGB 是紅、綠、藍三個光通道。
- 容易把數值 0 想成「沒有像素」或「透明」。
- 不理解 RGB 是加色模型：光越多越亮，沒有光就是黑。
- 不知道透明度通常由 alpha channel 表示，不是 RGB 三通道直接表示。
- 可能混淆黑色、白色與灰色的 RGB 數值模式。

### Core terms
- RGB：Red、Green、Blue 三個色光通道。
- True Color：常見以 RGB 三通道表示大量顏色的影像模式。
- 加色模型：用光相加形成顏色，光越多越亮。
- Channel：單一色彩通道的亮度值。
- Alpha channel：透明度通道，和 RGB 顏色值分開。

### Beginner explanation
既有 reviewed analysis 已符合非資工新手教學標準。它先說 RGB 是螢幕常用的加色模型，R、G、B 的數字代表紅光、綠光、藍光亮度。這個前置觀念很重要，因為本題不是在問油漆混色，而是在問螢幕發光。

套用規則時，`RGB(0,0,0)` 代表三種色光亮度都為 0，也就是沒有紅光、沒有綠光、沒有藍光。加色模型中沒有光就是黑色。透明則需要額外的 alpha channel，不能只從 `R(0), G(0), B(0)` 推出。

### Teaching tables
不需要。題目只判斷一組 RGB 數值，既有文字已能說明。若日後要補強，可加入簡短對照例：`RGB(0,0,0)` 黑、`RGB(255,255,255)` 白、`RGB(128,128,128)` 灰，但本題不是非加表格不可。

### Solving steps
1. 先辨認 R、G、B 是紅、綠、藍三個色光通道。
2. 套用加色模型：通道值越大，該色光越亮。
3. 檢查 `R(0), G(0), B(0)`：三個通道都沒有亮度。
4. 三種光都沒有輸出時，螢幕呈現黑色。
5. 排除透明，因為透明度需要 alpha channel。
6. 因此選 D。

### Option explanations
- A：錯誤。透明要看 alpha channel，不是 RGB 三個值本身。
- B：錯誤。白色通常是三通道都達最大值，例如 `RGB(255,255,255)`。
- C：錯誤。灰色通常是三通道相等且介於黑白之間，例如 `RGB(128,128,128)`。
- D：正確。`RGB(0,0,0)` 表示沒有紅、綠、藍光輸出，因此是黑色。

### Key takeaways
- RGB 是加色模型，數字代表三個色光通道的亮度。
- `RGB(0,0,0)` 是黑色，不是透明。
- 白色通常是三通道都很亮；灰色通常是三通道相等但不是 0 或最大值。
- 透明度要看 alpha channel。

### Answer note changes
不需要變更。既有 `answerNote: null` 合理，答案 D 沒有明顯疑義。

### Reviewer concerns
- Technical Reviewer：pass。RGB 加色模型與 alpha channel 區分正確。
- Novice Reviewer：pass。已先說明通道與加色模型，再套用到 `0,0,0`。
- Table Reviewer：pass。無表格也合理；表格可選但非必要。

## 114-Q023

### Question
對於機器學習中的過擬合(Overfitting)問題，下列敘述何者正確？

### Question type
機器學習模型評估概念題；判斷訓練誤差、測試誤差與泛化能力的關係。

### Source packet
- 題號：114-Q023
- Topic：過擬合
- 官方答案：D
- 選項：
  - A：訓練資料與測試資料的誤差皆低
  - B：增加訓練資料量一定會導致過擬合
  - C：模型對噪音資料完全忽略
  - D：訓練資料誤差低，但測試資料誤差高
- sourceRef：`114.pdf` page 3，`extractionStatus: needs-review`
- Reviewed baseline：既有 reviewed analysis 已標示 `answerVerification: verified`、`answerNote: null`，並已說明 overfitting、泛化能力、訓練誤差與測試誤差。

### Potential novice blockers
- 不知道訓練資料與測試資料分別用來做什麼。
- 容易把「訓練誤差低」誤認成模型一定好。
- 不理解泛化能力是模型處理新資料的能力。
- 不知道過擬合常把雜訊也學進去。
- 可能誤以為增加資料一定會造成過擬合。

### Core terms
- Overfitting：過擬合，模型太貼合訓練資料細節而不會泛化。
- 訓練誤差：模型在訓練資料上的錯誤程度。
- 測試誤差：模型在未見過資料上的錯誤程度。
- 泛化能力：模型面對新資料仍能正確預測的能力。
- Noise：資料中的雜訊或偶然細節。

### Beginner explanation
既有 reviewed analysis 已符合非資工新手教學標準。它沒有只背「訓練低、測試高」，而是先解釋模型不只要答對練習題，還要答對沒看過的新題目，這就是泛化能力。這個比喻對非資工新手很重要。

過擬合的核心規則是：模型把訓練資料的細節甚至雜訊記得太死，所以訓練集表現漂亮，但測試集或真實新資料表現差。套回本題，只有 D 同時說到訓練資料誤差低、測試資料誤差高。

### Teaching tables
可選，不強制。既有分析已達標；但本題是「模型狀態分類」概念，若主代理想加 teachingTables，可用一張小表比較「良好泛化、過擬合、欠擬合」的訓練誤差與測試誤差。

建議表格草案：

| 狀態 | 訓練誤差 | 測試誤差 | 考試判斷 |
| --- | --- | --- | --- |
| 良好泛化 | 低 | 低 | 訓練與新資料都表現好 |
| 過擬合 | 低 | 高 | 訓練好、測試差 |
| 欠擬合 | 高 | 高 | 連訓練資料都沒學好 |

### Solving steps
1. 先抓住過擬合的目的判斷：模型是否能處理沒看過的新資料。
2. 檢查訓練誤差：過擬合通常在訓練資料上很低。
3. 檢查測試誤差：過擬合通常在測試資料上很高。
4. 排除 A，因為訓練與測試都低代表泛化良好。
5. 排除 B，因為增加訓練資料通常有機會降低過擬合，不是一定導致過擬合。
6. 排除 C，因為過擬合常見問題是把雜訊也學進去。
7. 因此選 D。

### Option explanations
- A：錯誤。訓練與測試誤差都低通常代表模型泛化良好。
- B：錯誤。增加訓練資料不一定造成過擬合，很多時候反而能降低過擬合。
- C：錯誤。過擬合常把噪音也學進去，不是完全忽略噪音。
- D：正確。訓練誤差低、測試誤差高，是過擬合的典型特徵。

### Key takeaways
- 過擬合的核心是「訓練好、測試差」。
- 訓練誤差低不代表模型一定可靠。
- 泛化能力要看未見過資料上的表現。
- 過擬合常把訓練資料的偶然細節或雜訊也學進去。

### Answer note changes
不需要變更。既有 `answerNote: null` 合理，答案 D 沒有明顯疑義。

### Reviewer concerns
- Technical Reviewer：pass。過擬合定義與誤差關係正確。
- Novice Reviewer：pass。已補足訓練 / 測試 / 泛化三個前置概念。
- Table Reviewer：pass with optional improvement。若新增表格，需確認 headers 與 rows 欄位數一致；不新增表格也可接受。

## 114-Q024

### Question
關於 SMP 多重處理器系統的敘述，下列何者有誤？

### Question type
計算機架構概念題；判斷 SMP 的基本特徵並找出錯誤敘述。

### Source packet
- 題號：114-Q024

- 官方答案：C
- 選項：
  - A：CPU 與 CPU 之間共用記憶體
  - B：當 CPU 數量過多時，記憶體存取可能成為效能瓶頸
  - C：當任一 CPU 故障通常會導致整個系統故障或停擺

### Potential novice blockers

### Core terms
- SMP：對稱多處理器，多個 CPU 角色相近並由同一作業系統管理。

- 對稱：CPU 角色不是主從架構，而是地位相近。
- 記憶體瓶頸：多顆 CPU 同時搶用記憶體造成效能限制。

### Beginner explanation

本題最重要的解題提醒是「有誤」兩字。A、B、D 都可用典型 SMP 特徵解釋：共享記憶體、可能有記憶體瓶頸、可提高處理能力。C 把 SMP 說成任一 CPU 故障通常就讓整體停擺，這不是 SMP 的必要特性，因此是錯誤敘述。

4. 檢查 B：CPU 數量變多後，記憶體存取可能成為瓶頸，敘述合理。
5. 檢查 C：SMP 不要求任一 CPU 故障就必然讓整個系統停擺，這是錯誤敘述。
6. 檢查 D：多處理器可平行處理任務，提高處理能力，敘述合理。

### Option explanations

### Key takeaways

## 114-Q025

### Question
下列何者非屬 CPU 的組成元件？

### Question type
計算機架構分類題；辨認 CPU 基本組成元件與記憶體技術的差異。

### Source packet

  - A：ALU
  - B：control unit

### Potential novice blockers

### Core terms
