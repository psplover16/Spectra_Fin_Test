# 1. 二元樹基本名詞

## 一、名詞解釋

二元樹 Binary Tree 是一種樹狀資料結構。
本身只規定每個節點最多只能有兩個子節點，分別稱為 左子節點(left child)、右子節點(right child) 

常見名詞：

| 名詞 | 說明 |
|---|---|
| 節點 Node | 樹中的每一個資料單位 |
| 根節點 Root | 最上面的節點 |
| 父節點 Parent | 某節點的上一層節點 |
| 子節點 Child | 某節點的下一層節點 |
| 兄弟節點 Sibling | 同一個父節點底下的節點 |
| 葉節點 Leaf | 沒有子節點的節點 |------------------------------------------
| 內部節點 Internal Node | 不是葉節點的節點 |
| 子樹 Subtree | 從某節點往下形成的一棵樹 |
| 深度 Depth | 從根節點走到某節點的邊數 |------------------------------------------
| 高度 Height | 從某節點走到最深葉節點的邊數 |------------------------------------------
| 階層 Level | 節點所在層級，不同教材可能從 0 或 1 開始算 |

---

## 二、核心想法

二元樹用來表示「階層關係」。

例如：

```text
公司組織
資料夾結構
決策流程
運算式結構
搜尋資料
優先順序管理
```

二元樹本身只規定「每個節點最多兩個子節點」。

它還沒有規定：

```text
左邊一定比較小？沒有
右邊一定比較大？沒有
一定要平衡？沒有
一定要填滿？沒有
```

所以 BST、AVL、紅黑樹、Heap 都可以看成是「在二元樹基礎上，再加上不同規則」。

---

## 三、如何使用

範例：

```text
        A
       / \
      B   C
     /
    D
```

分析：

```text
根節點：A
A 的子節點：B、C
B 的子節點：D
葉節點：C、D

A 的深度：0
B 的深度：1
D 的深度：2
D 的高度：0
B 的高度：1
A 的高度：2
```

# 2. 二元樹種類

## 一、名詞解釋

國考常考二元樹種類：

```text
二元樹 Binary Tree
滿二元樹 Full Binary Tree
完美二元樹 Perfect Binary Tree
完全二元樹 Complete Binary Tree
平衡二元樹 Balanced Binary Tree
歪斜樹 Skewed Tree
```

## 三、如何使用

### 2-1. 滿二元樹 Full Binary Tree

定義：每個節點要嘛沒有子節點，要嘛有兩個子節點。不能只有一個子節點。


### 2-2. 完美二元樹 Perfect Binary Tree

定義：所有內部節點都有兩個子節點，且所有葉節點在同一層。


### 2-3. 完全二元樹 Complete Binary Tree

定義：除了最後一層以外，其他層都要填滿。最後一層必須由左到右填。

---

2-4.平衡二元樹 Balanced Binary Tree
平衡二元樹 是一種「左右子樹高度差不會太大的二元樹」。 但要注意： 「平衡二元樹」是一個比較廣義的概念，不一定只指 AVL 樹。



### 2-4. 歪斜樹 Skewed Tree

定義：每個節點幾乎都只有單邊子節點，形狀像一條線。
這種樹查找效率會很差，接近線性搜尋。


### 國考速記

```text
Full：每個節點 0 或 2 個小孩
Perfect：每層全滿，葉子同層
Complete：最後一層從左到右填
Balanced：高度差不會太誇張
Skewed：歪成一條線
```

# 3. 二元樹公式與性質

## 一、名詞解釋

國考常考二元樹公式，通常和以下名詞有關：

```text
高度 h
層級 i
節點總數 n
葉節點數 n0
度為 2 的節點數 n2
```

「度」的意思是：一個節點有幾個子節點。
度為 0：沒有子節點，也就是葉節點
度為 1：有一個子節點
度為 2：有兩個子節點


## 二、核心想法

公式題的重點是：

```text
二元樹每往下一層，最多節點數會乘以 2。
```

因為每個節點最多有兩個子節點。

---

## 三、如何使用

### 公式 1：第 i 層最多節點數

如果根節點算第 0 層：

```text
第 i 層最多節點數 = 2^i
```

範例：

```text
第 0 層：2^0 = 1
第 1 層：2^1 = 2
第 2 層：2^2 = 4
第 3 層：2^3 = 8
```

---

### 公式 2：高度為 h 的二元樹最多節點數

如果根節點高度算 0， 最多節點數 = 2^(h+1) - 1


---

### 公式 3：葉節點數與度為 2 節點數

在非空二元樹中：
葉節點數 = 度為 2 的節點數 + 1

### 公式 4：完全二元樹的陣列關係

"若陣列從 index 1 開始(條件)"：
節點 i 的左子節點 = 2i
節點 i 的右子節點 = 2i + 1
節點 i 的父節點 = floor(i / 2)


範例：

```text
        A
       / \
      B   C
     / \
    D   E
```

陣列表示：

```text
index: 1 2 3 4 5
value: A B C D E
```

B 在 index 2：

```text
B 的左子節點 = 2 × 2 = 4，也就是 D
B 的右子節點 = 2 × 2 + 1 = 5，也就是 E
B 的父節點 = floor(2 / 2) = 1，也就是 A
```

# 4. 二元樹走訪 Traversal

## 一、名詞解釋

走訪 Traversal 是指：

```text
按照某種固定順序，把樹上的每個節點都拜訪一次。
```

常見走訪：

```text
前序 Preorder
中序 Inorder
後序 Postorder
層序 Level-order
```

---

## 二、核心想法

前、中、後是看「根節點」在什麼時候被處理。

```text
前序：根在前面，喊>左>右
中序：根在中間
後序：根在後面
層序：從上到下，每層由左到右。一層一層看
```


---

# 5. 由走訪結果還原二元樹

## 一、名詞解釋

還原二元樹是指：給你某些走訪結果，要求你畫回原本的樹。

前序 + 中序：可以唯一還原
後序 + 中序：可以唯一還原
前序 + 後序：通常不能唯一還原

## 二、核心想法

關鍵記法： 中序重要，只要知道根在哪裡，就可以把左子樹和右子樹分開。

前序第一個是根
後序最後一個是根
中序可以切左右子樹




---

# 6. 二元搜尋樹 BST

## 一、名詞解釋

BST 是 Binary Search Tree，中文是二元搜尋樹。

它是二元樹的一種，但多了一個大小規則： 左子樹的值 < 右子樹的值



## 二、核心想法

BST 解決的是「快速搜尋」問題。

普通陣列或串列找資料，可能要從頭找到尾。

BST 可以利用大小關係縮小範圍：

```text
目標比目前節點小 → 往左
目標比目前節點大 → 往右
```

---

## 三、如何使用

### 6-1. 查找 Search

查找 7：

```text
        10
       /  \
      5    15
     / \     \
    3   7     20
```

步驟：

```text
7 < 10，往左到 5
7 > 5，往右到 7
找到 7
```

---

### 6-2. 插入 Insert

插入 8：

```text
8 < 10，往左
8 > 5，往右
8 > 7，放到 7 的右邊
```

結果：

```text
        10
       /  \
      5    15
     / \     \
    3   7     20
         \
          8
```

---

### 6-3. 刪除 Delete

BST 刪除有三種情況。

#### 情況 1：刪除葉節點

刪除 3：

```text
        10
       /  \
      5    15
       \     \
        7     20
```

直接刪掉即可。

---

#### 情況 2：刪除只有一個子節點的節點

刪除 15：

原本：

```text
        10
       /  \
      5    15
             \
              20
```

刪除後：

```text
        10
       /  \
      5    20
```

把 20 接上來。

---

#### 情況 3：刪除有兩個子節點的節點

刪除 10：

```text
        10
       /  \
      5    15
     / \     \
    3   7     20
```

可以用：

```text
中序前驅：左子樹中最大的值
中序後繼：右子樹中最小的值
```

例如使用中序後繼 15 替換 10：

```text
        15
       /  \
      5    20
     / \
    3   7
```

---

### BST 國考重點

```text
BST 中序走訪會得到由小到大的排序結果。
```

範例：

```text
        10
       /  \
      5    15
     / \     \
    3   7     20
```

中序：

```text
3 5 7 10 15 20
```

---

# 7. AVL 樹

## 一、名詞解釋

AVL 樹是一種「自我平衡二元搜尋樹」。

它是 BST，但加上一個嚴格的平衡限制：

```text
任一節點的左子樹高度與右子樹高度，差距最多只能是 1。
```

平衡因子 Balance Factor：

```text
BF = 左子樹高度 - 右子樹高度
```

合法值：

```text
-1、0、1
```

---

## 二、核心想法

AVL 解決的是：

```text
避免 BST 因為插入順序不好而歪成一條線。
```

普通 BST 如果依序插入：

```text
1, 2, 3, 4, 5
```

可能變成：

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

這樣查找效率會變差。

AVL 會透過旋轉把樹調回平衡。

---

## 三、如何使用

AVL 插入後，如果某個節點平衡因子變成：

```text
2 或 -2
```

代表不平衡，需要旋轉。

AVL 四種旋轉情況：

```text
LL：右旋
RR：左旋
LR：先左旋，再右旋
RL：先右旋，再左旋
```

---

### 7-1. LL 型

插入順序：

```text
30, 20, 10
```

暫時變成：

```text
      30
     /
    20
   /
  10
```

這是左左型 LL。

處理方式：

```text
對 30 右旋
```

結果：

```text
      20
     /  \
    10   30
```

---

### 7-2. RR 型

插入順序：

```text
10, 20, 30
```

暫時變成：

```text
10
  \
   20
     \
      30
```

這是右右型 RR。

處理方式：

```text
對 10 左旋
```

結果：

```text
      20
     /  \
    10   30
```

---

### 7-3. LR 型

插入順序：

```text
30, 10, 20
```

暫時變成：

```text
      30
     /
    10
      \
       20
```

這是左右型 LR。

處理方式：

```text
先對 10 左旋
再對 30 右旋
```

結果：

```text
      20
     /  \
    10   30
```

---

### 7-4. RL 型

插入順序：

```text
10, 30, 20
```

暫時變成：

```text
10
  \
   30
   /
  20
```

這是右左型 RL。

處理方式：

```text
先對 30 右旋
再對 10 左旋
```

結果：

```text
      20
     /  \
    10   30
```

---

### AVL 國考速記

```text
AVL = BST + 平衡因子
BF = 左高 - 右高
BF 只能是 -1、0、1
LL 右旋
RR 左旋
LR 先左旋再右旋
RL 先右旋再左旋
```

---

# 8. 紅黑樹 Red-Black Tree

## 一、名詞解釋

紅黑樹 Red-Black Tree 是一種「自我平衡的二元搜尋樹」。

它和 AVL 一樣，都是 BST 的進階版本。

但它們不是同一種樹。

```text
AVL：用左右高度差維持平衡
紅黑樹：用節點顏色規則維持平衡
```

紅黑樹中，每個節點會被標記成：

```text
紅色 Red
黑色 Black
```

例如：

```text
        10(B)
       /     \
    5(R)     15(R)
```

其中：

```text
B = Black 黑色
R = Red 紅色
```

---

## 二、核心想法

紅黑樹解決的問題是：

```text
讓 BST 在插入、刪除後，仍然不會歪得太嚴重。
```

它不像 AVL 那麼嚴格要求左右高度差最多為 1。

紅黑樹的想法是：

```text
不要求完全平衡，只要求不要太不平衡。
```

所以可以這樣記：

```text
AVL：嚴格平衡
紅黑樹：大致平衡
```

---

## 三、如何使用

紅黑樹主要依靠五個規則。

### 規則 1：每個節點不是紅色，就是黑色

```text
10(B)
```

或：

```text
10(R)
```

---

### 規則 2：根節點一定是黑色

```text
      10(B)
```

根節點不能是紅色。

---

### 規則 3：所有 NIL 空節點都是黑色

NIL 可以先理解成「空的子節點」。

例如：

```text
      10(B)
     /    \
   NIL    NIL
```

這兩個 NIL 都算黑色。

初學可以先記：

```text
空節點也算黑色，只是畫圖時常省略。
```

---

### 規則 4：紅色節點不能有紅色子節點

不合法：

```text
    10(R)
    /
  5(R)
```

因為紅色下面接紅色。

合法：

```text
    10(B)
    /
  5(R)
```

---

### 規則 5：任一節點到所有 NIL 葉節點，黑色節點數量要相同

這個數量稱為黑高 Black Height。

範例：

```text
        10(B)
       /     \
    5(R)     15(R)
```

從 10 走到左邊 NIL：

```text
10(B) → 5(R) → NIL(B)
```

黑色節點數：

```text
10、NIL，共 2 個
```

從 10 走到右邊 NIL：

```text
10(B) → 15(R) → NIL(B)
```

黑色節點數：

```text
10、NIL，共 2 個
```

黑色數量一樣，所以合法。

---

## 8-1. 紅黑樹為什麼能保持平衡？

紅黑樹透過兩個重要限制，避免樹歪太嚴重：

```text
1. 紅色節點不能連續
2. 每條路徑的黑色節點數量要相同
```

因為紅色不能連續，所以最長路徑也不能一直塞紅色節點。

因為黑色數量要一樣，所以某條路徑不能比另一條路徑多太多黑色節點。

因此紅黑樹可以保證高度維持在 O(log n)。

---

## 8-2. 紅黑樹基本操作

紅黑樹常見操作：

```text
查找 Search
插入 Insert
刪除 Delete
```

其中：

```text
查找：和 BST 幾乎一樣
插入：先照 BST 插入，再修正顏色或旋轉
刪除：刪除後也可能需要修正，考試通常較少要求完整手算
```

---

## 8-3. 紅黑樹查找 Search

因為紅黑樹本質仍然是 BST，所以查找不用管顏色。

範例：查找 7

```text
        10(B)
       /     \
    5(R)     15(R)
      \
      7(B)
```

步驟：

```text
7 < 10，往左
7 > 5，往右
找到 7
```

顏色的用途是維持平衡，不是判斷大小。

---

## 8-4. 紅黑樹插入 Insert

紅黑樹插入流程：

```text
步驟 1：先照 BST 規則插入
步驟 2：新節點通常先設為紅色
步驟 3：檢查是否違反紅黑樹規則
步驟 4：如果違反，就用重新著色或旋轉修正
步驟 5：最後根節點改成黑色
```

---

## 8-5. 為什麼新節點通常先設成紅色？

因為如果新節點設成黑色，可能會破壞規則 5：

```text
每條路徑的黑色節點數量要一樣。
```

插入一個黑色節點，某條路徑的黑色數量可能突然多 1。

所以新節點通常先設成紅色。

紅色節點不會增加黑色節點數，因此比較不容易破壞黑高。

---

## 8-6. 旋轉 Rotation

旋轉是紅黑樹調整形狀的方法。

旋轉不會破壞 BST 的大小順序，只是改變節點位置。

### 左旋 Left Rotation

原本：

```text
    10
      \
       20
```

左旋後：

```text
      20
     /
   10
```

理解：

```text
右邊太重時，把右邊的節點拉上來。
```

---

### 右旋 Right Rotation

原本：

```text
      20
     /
   10
```

右旋後：

```text
    10
      \
       20
```

理解：

```text
左邊太重時，把左邊的節點拉上來。
```

---

## 8-7. 插入範例：依序插入 10、20、30

### 插入 10

新節點先設紅色：

```text
10(R)
```

但根節點必須是黑色，所以改成：

```text
10(B)
```

---

### 插入 20

20 比 10 大，放右邊：

```text
10(B)
   \
   20(R)
```

沒有違反規則。

---

### 插入 30

30 比 10 大，往右。

30 比 20 大，再往右：

```text
10(B)
   \
   20(R)
      \
      30(R)
```

這裡違反規則：

```text
紅色 20 下面接紅色 30
```

這是 RR 型。

處理方式：

```text
對 10 做左旋
```

旋轉後：

```text
      20
     /  \
   10    30
```

重新上色：

```text
      20(B)
     /    \
  10(R)  30(R)
```

檢查：

```text
根節點是黑色，合法
紅色節點 10、30 沒有紅色子節點，合法
左右路徑黑色節點數量相同，合法
```

---

## 8-8. 插入範例：依序插入 10、5、1

暫時變成：

```text
      10(B)
      /
    5(R)
    /
  1(R)
```

違反規則：

```text
紅色 5 下面接紅色 1
```

這是 LL 型。

處理方式：

```text
對 10 做右旋
```

旋轉後：

```text
      5
     / \
    1   10
```

重新上色：

```text
      5(B)
     /   \
   1(R) 10(R)
```

---

## 8-9. 插入範例：叔叔節點是紅色

假設目前：

```text
        10(B)
       /     \
    5(R)    15(R)
```

插入 1：

```text
        10(B)
       /     \
    5(R)    15(R)
    /
  1(R)
```

問題：

```text
5(R) 和 1(R) 連續紅色
```

新節點是 1：

```text
父節點：5
祖父節點：10
叔叔節點：15
```

因為父節點與叔叔節點都是紅色，所以處理方式是重新著色：

```text
父節點改黑色
叔叔節點改黑色
祖父節點改紅色
```

變成：

```text
        10(R)
       /     \
    5(B)    15(B)
    /
  1(R)
```

但是根節點必須是黑色，所以最後 10 改回黑色：

```text
        10(B)
       /     \
    5(B)    15(B)
    /
  1(R)
```

---

## 8-10. 插入時常見四種形狀

如果父節點與新節點都是紅色，可能需要旋轉。

令：

```text
G = Grandparent 祖父節點
P = Parent 父節點
N = New node 新節點
```

### LL 型

```text
      G
     /
    P
   /
  N
```

處理：

```text
對 G 右旋
```

---

### RR 型

```text
  G
   \
    P
     \
      N
```

處理：

```text
對 G 左旋
```

---

### LR 型

```text
      G
     /
    P
     \
      N
```

處理：

```text
先對 P 左旋
再對 G 右旋
```

---

### RL 型

```text
  G
   \
    P
   /
  N
```

處理：

```text
先對 P 右旋
再對 G 左旋
```

---

## 8-11. AVL 與紅黑樹比較

| 比較 | AVL 樹 | 紅黑樹 |
|---|---|---|
| 類型 | 自我平衡 BST | 自我平衡 BST |
| 平衡方式 | 用高度差 | 用顏色與黑高 |
| 平衡程度 | 較嚴格 | 較寬鬆 |
| 查找速度 | 通常略快 | 很快 |
| 插入刪除 | 旋轉可能較多 | 調整通常較少 |
| 適合場景 | 查詢很多 | 插入、刪除也頻繁 |

速記：

```text
AVL：高度平衡，查詢強
紅黑樹：顏色平衡，更新穩
```

---

## 8-12. 紅黑樹國考重點整理

一句話定義：

```text
紅黑樹是一種每個節點帶有紅色或黑色標記的自我平衡二元搜尋樹，
用來維持查找、插入、刪除效率在 O(log n)。
```

必背規則：

```text
1. 每個節點不是紅色就是黑色
2. 根節點是黑色
3. NIL 空葉節點是黑色
4. 紅色節點不能有紅色子節點
5. 任一節點到其所有 NIL 葉節點的黑色節點數相同
```

必背操作：

```text
重新著色 recoloring
左旋 left rotation
右旋 right rotation
```

時間複雜度：

| 操作 | 時間複雜度 |
|---|---|
| 查找 | O(log n) |
| 插入 | O(log n) |
| 刪除 | O(log n) |

最短速記：

```text
紅黑樹 = BST + 顏色規則 + 旋轉修正
目的 = 避免樹歪掉
特色 = 不追求完全平衡，但保證不會太歪
效率 = 查找、插入、刪除都是 O(log n)
```

# 9. Heap 堆積

## 一、名詞解釋

Heap 是一種特殊的二元樹，通常必須是：

```text
完全二元樹 Complete Binary Tree
```

Heap 分成兩種：

```text
最大堆 Max Heap
最小堆 Min Heap
```

---

## 二、核心想法

Heap 主要解決的是：

```text
快速取得最大值或最小值。
```

它常用於：

```text
優先佇列 Priority Queue
排程問題
Heap Sort
找最大值或最小值
```

---

## 三、如何使用

### 最大堆 Max Heap

規則：

```text
父節點 >= 子節點
```

範例：

```text
        50
       /  \
      30   40
     / \
    10  20
```

最大值一定在根節點。

---

### 最小堆 Min Heap

規則：

```text
父節點 <= 子節點
```

範例：

```text
        10
       /  \
      20   30
     / \
    40  50
```

最小值一定在根節點。

---

### Heap 與 BST 差異

| 比較 | Heap | BST |
|---|---|---|
| 主要用途 | 快速取最大或最小 | 快速查找特定值 |
| 形狀 | 必須是完全二元樹 | 不一定完全 |
| 規則 | 父子大小關係 | 左小右大 |
| 中序走訪 | 不一定排序 | 會得到排序結果 |
| 根節點 | 最大或最小 | 不一定最大或最小 |

國考速記：

```text
Heap 看父子，BST 看左右。
Heap 取極值，BST 找資料。
```

---

# 10. 線索二元樹 Threaded Binary Tree

## 一、名詞解釋

線索二元樹是一種改良的二元樹。

普通二元樹中，很多節點的左指標或右指標是空的。

線索二元樹把這些空指標拿來指向：

```text
走訪順序中的前驅 predecessor
走訪順序中的後繼 successor
```

---

## 二、核心想法

它解決的問題是：

```text
不用遞迴，也不用堆疊，就能更方便地走訪二元樹。
```

---

## 三、如何使用

假設中序走訪結果是：

```text
D B E A C
```

如果 E 沒有右子節點，可以讓 E 的右線索指向 A。

因為在中序走訪中，A 是 E 的下一個節點。

```text
E 的中序後繼 = A
```

國考通常考定義，不太會要求大量實作。

---

# 11. 運算式樹 Expression Tree

## 一、名詞解釋

運算式樹用來表示數學或程式中的運算式。

例如：

```text
(a + b) * c
```

可以表示成：

```text
        *
       / \
      +   c
     / \
    a   b
```

---

## 二、核心想法

運算式樹可以把運算順序清楚表示出來。

```text
內部節點通常是運算子
葉節點通常是運算元
```

例如：

```text
+、-、*、/ 是運算子
a、b、c、數字 是運算元
```

---

## 三、如何使用

以上面的樹為例：

```text
        *
       / \
      +   c
     / \
    a   b
```

前序：

```text
* + a b c
```

代表前置式 prefix。

中序：

```text
a + b * c
```

但正確應補括號：

```text
((a + b) * c)
```

後序：

```text
a b + c *
```

代表後置式 postfix。

---

# 12. Huffman Tree 赫夫曼樹

## 一、名詞解釋

Huffman Tree 是一種常用於資料壓縮的樹。

它根據資料出現頻率建立編碼。

核心原則：

```text
出現頻率高的資料，用較短編碼
出現頻率低的資料，用較長編碼
```

---

## 二、核心想法

假設：

```text
A 出現 50 次
B 出現 20 次
C 出現 10 次
D 出現 5 次
```

A 最常出現，所以希望 A 的編碼比較短。

D 較少出現，所以 D 的編碼可以比較長。

這樣整體資料長度可以變短。

---

## 三、如何使用

建立 Huffman Tree 的基本方法：

```text
步驟 1：把每個資料看成一棵樹
步驟 2：每次挑權重最小的兩棵樹合併
步驟 3：合併後的新權重 = 兩者權重相加
步驟 4：重複直到只剩一棵樹
```

範例：

```text
A: 5
B: 9
C: 12
D: 13
E: 16
F: 45
```

合併流程：

```text
5 + 9 = 14
12 + 13 = 25
14 + 16 = 30
25 + 30 = 55
45 + 55 = 100
```

國考常考：

```text
Huffman Tree 建立流程
Huffman Code
WPL 加權路徑長度
前綴碼 Prefix Code
```

速記：

```text
Huffman Tree = 每次挑兩個最小權重合併
```

```text
二元樹國考主線：

基本名詞
→ 樹的種類
→ 公式
→ 走訪
→ 還原樹
→ BST
→ AVL
→ 紅黑樹
→ Heap
→ 線索二元樹
→ 運算式樹
→ Huffman Tree
```

分類速記：

```text
BST / AVL / 紅黑樹：用來查找
Heap：用來取最大或最小
Expression Tree：用來表示運算式
Huffman Tree：用來壓縮編碼
Threaded Binary Tree：用來改善走訪
```

AVL 與紅黑樹差異速記：

```text
AVL：高度平衡，規則嚴格，查找略強

```

Heap 與 BST 差異速記：

```text
Heap 看父子大小，不看左右大小。
BST 看左右大小，不保證根是最大或最小。
```

```text
紅黑樹 = BST + 紅黑顏色 + 黑高一致 + 旋轉修正
```

# 15. 考前背誦清單

## 必背一：二元樹種類

```text
Full：每個節點 0 或 2 個小孩
Perfect：每層全滿，葉節點同層
Complete：最後一層從左到右填
Skewed：歪成一條線
```

## 必背二：走訪

```text
前序：根左右
中序：左根右
後序：左右根
層序：由上到下、由左到右
```

## 必背三：還原樹

```text
前序第一個是根
後序最後一個是根
中序用來切左右子樹
```

## 必背四：BST

```text
左小右大
中序走訪會得到排序結果
刪除兩個子節點時，用中序前驅或中序後繼替換
```

## 必背五：AVL

```text
BF = 左高 - 右高
合法 BF：-1、0、1
LL 右旋
RR 左旋
LR 先左旋再右旋
RL 先右旋再左旋
```

## 必背六：紅黑樹

```text
1. 每個節點紅或黑
2. 根節點黑
3. NIL 空節點黑
4. 紅節點不能接紅節點
5. 任一節點到 NIL 的黑色節點數相同
```

## 必背七：Heap

```text
Heap 是完全二元樹
Max Heap：父 >= 子
Min Heap：父 <= 子
陣列 index 從 1 開始時：左 2i，右 2i+1，父 i/2
```

# 16. 常見混淆點整理

## 混淆 1：紅黑樹是不是 AVL？

不是。

```text
它們都是自我平衡 BST。
AVL 用高度差平衡。
紅黑樹用顏色與黑高平衡。
```

---

## 混淆 2：Heap 是不是 BST？

不是。

```text
Heap 只要求父子大小關係。
BST 要求左子樹 < 根 < 右子樹。
```

---

## 混淆 3：完全二元樹是不是完美二元樹？

不一定。

```text
完美二元樹一定是完全二元樹。
完全二元樹不一定是完美二元樹。
```

範例：

```text
        A
       / \
      B   C
     / \
    D   E
```

這是完全二元樹，但不是完美二元樹。

---

## 混淆 4：BST 中序為什麼會排序？

因為 BST 的規則是：

```text
左子樹 < 根 < 右子樹
```

中序剛好是：

```text
左 → 根 → 右
```

所以會從小到大輸出。

---

## 混淆 5：紅黑樹新節點為什麼先設紅色？

因為紅色節點不會增加黑高。

如果新節點先設黑色，某條路徑黑色數量可能多 1，容易破壞黑高一致。

---

# 17. 一頁版總複習

```text
二元樹：每個節點最多兩個子節點。

Full：每個節點 0 或 2 個子節點。
Perfect：每層全滿，葉節點同層。
Complete：最後一層從左到右填。

前序：根左右。
中序：左根右。
後序：左右根。
層序：一層一層看。

BST：左小右大，中序會排序。
AVL：BST + BF 限制，BF = -1、0、1。
紅黑樹：BST + 紅黑規則 + 黑高一致。
Heap：完全二元樹，用來快速取最大或最小。
線索二元樹：用空指標指向前驅或後繼。
運算式樹：用樹表示運算式。
Huffman Tree：每次挑兩個最小權重合併，用於壓縮。
```

# 18. 建議練習題型

## 題型 1：判斷樹的種類

給一棵樹，判斷它是：

```text
滿二元樹？
完美二元樹？
完全二元樹？
BST？
Heap？
AVL？
紅黑樹？
```

---

## 題型 2：寫出走訪結果

給一棵樹，寫出：

```text
前序
中序
後序
層序
```

---

## 題型 3：由走訪結果還原樹

給：

```text
前序 + 中序
或
後序 + 中序
```

要求畫出原本的樹。

---

## 題型 4：BST 操作

練習：

```text
查找
插入
刪除葉節點
刪除一個子節點的節點
刪除兩個子節點的節點
```

---

## 題型 5：AVL 旋轉

練習判斷：

```text
LL
RR
LR
RL
```

並畫出旋轉後結果。

---

## 題型 6：紅黑樹規則判斷

練習檢查：

```text
根是不是黑色？
有沒有連續紅色？
每條路徑黑色節點數是否相同？
```

---

## 題型 7：Heap 陣列表示

練習：

```text
由樹轉陣列
由陣列畫樹

```

# 19. 結論

二元樹國考的核心不是只背名詞，而是要看懂「規則」。

可以用這句話收斂：

```text
二元樹是基礎骨架，
BST 加上左小右大，
AVL 加上高度平衡，
紅黑樹加上顏色平衡，
Heap 加上父子大小與完全二元樹限制。
```

如果時間有限，最先熟練：

```text
走訪、還原樹、BST、AVL、Heap、紅黑樹規則
```

這些最容易出現在選擇題、計算題與手算題中。
