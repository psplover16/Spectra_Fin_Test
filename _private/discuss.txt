Memory Hierarchy（記憶體階層）-電腦不是只用一種記憶體，而是把不同速度、容量、價格的儲存設備，依照層級排列起來使用。

層級	名稱	速度	容量	內容例      
第 1 層	    Register 暫存器	                最快	最小	CPU 正在計算的數字
第 2 層	    Cache 快取記憶體	            很快	很小	最近常用的資料或指令
第 3 層	    Main Memory 主記憶體 / RAM      中等	較大	正在執行的程式和資料
第 4 層	    SSD / HDD 輔助儲存體	        慢      很大	作業系統、遊戲、影片、文件
第 5 層	    外部儲存 / 雲端 / 磁帶	        最慢     最大	 備份資料、歷史資料、雲端檔案

區域性 Locality，電腦程式常常會重複使用最近用過的資料，或使用附近的資料。
時間區域性 Temporal Locality：剛剛用過的資料，很可能等一下又會用到。
空間區域性 Spatial Locality：用到某個位置的資料後，很可能接著會用附近位置的資料。

AVL 樹是自我平衡的二元搜尋樹。
一般 BST 只要求左子樹的值小於節點本身，右子樹的值大於節點本身，
但不保證樹的高度平衡。

AVL 樹除了符合 BST 的搜尋規則外，
還要求每個節點的左右子樹高度差最多為 1。
當插入或刪除造成不平衡時，AVL 樹會透過旋轉調整，
使樹維持平衡，因此搜尋效率比一般可能歪斜的 BST 更穩定。

平衡因子 = 左子樹高度 - 右子樹高度
前序走訪(Preorder)
中序走訪(Inorder)
其後序走訪(Postorder)
--
紅黑樹主要解決這個問題：讓二元搜尋樹在插入、刪除資料後，仍然保持接近平衡，避免退化成一條線。

補數（complement）是對於給定的進位制，相加後能使自然數 a 的位數增加 1 的最小的數。
補數（Complement）是為了解決電腦減法運算而發展出的數學概念。

十進位補數
假設系統基數為 r：
r 的補數（基數補數，如 10 補數）： N 的 r 補數為 \(r^n - N\)（n 為位數）。例如在三位數中，數字 345 的 10 補數為 1000 - 345 = 655。
r-1 的補數（減一補數，如 9 補數）： N 的 r-1 補數為 \((r^n - 1) - N\)。例如數字 345 的 9 補數為 999 - 345 = 654。

二進位補數系統
一補數（1's Complement / 1的補數）計算方法： 將原數字的每個位元進行反轉，也就是 0 變 1、1 變 0（即 NOT 運算）
二補數（2's Complement / 2的補數）計算方法： 先求出該數的「一補數」，再將結果加上 1。

Sum 叫做本位和；這一位加完之後，這一格留下來的結果。
Carry 叫做進位；這一位加太大了，要往左邊多送一個 1。

半加器： 只算 A + B，輸出 Sum 和 Carry。
全加器： 算 A + B + Cin，多了「前一位進位」，Cin是前一位傳進來的進位。

溢位要看的是：符號位附近的進位狀況，或正負號是否不合理。Overflow = 最高位的進位輸入 XOR 最高位的進位輸出

資料庫:

Transaction(交易): 把多個步驟綁成一個不可分割的整體。如果中途出錯，已經做的部分會被全部撤銷（rollback），回到開始前的狀態，就像什麼都沒發生過。
Atomicity（原子性）：全部成功或全部失敗，沒有做一半。  (僅保證 自己的修改可以全部取消 或 全部成功)
Consistency（一致性）：交易前後資料都符合規則（例如總金額守恆）。 (交易完成後，資料庫要維持合法狀態，不違反規則)
Isolation（隔離性）：多筆交易同時跑時，彼此不會互相干擾，結果跟一筆一筆做一樣。 (但是 SQL 有不同隔離層級。)
Durability（持久性）：交易一旦成功，資料就永久保存，就算斷電也不會丟。

Commit 表示交易正式確認，資料真的存進資料庫。
Rollback 表示交易取消，資料要恢復原狀。


Dirty Read 是指：一個交易讀到了另一個交易「尚未 Commit」的資料。
Dirty Read 不會自動 Rollback，因為它不是資料庫判定的「執行錯誤」。 它是你選擇較低隔離層級後，資料庫允許發生的現象。 (也就是 READ UNCOMMITTED 放寬了 ACID 裡的 Isolation，所以可能發生 Dirty Read。)

資料庫交易異常整理
Dirty Read：
讀到別人還沒 COMMIT 的資料。
Non-repeatable Read：
同一交易內，同一筆資料讀兩次，值不同。
Phantom Read：
同一交易內，同一條件查兩次，筆數不同。
Lost Update：
兩個交易同時更新同一筆資料，導致其中一個更新被覆蓋。
Read Skew / Inconsistent Read(讀取偏斜)：
同一交易讀到多筆相關資料，但不是同一時間點的狀態，合起來不一致。
Write Skew(寫入偏斜)：
兩個交易各自修改不同資料，各自看都合法，但最後整體違反規則。

正規化是關聯式資料庫中整理資料表的方法。目的是 同一種資料不要到處重複存，把不同主題拆成不同資料表，再用主鍵、外鍵連起來，避免新增、刪除、修改異常。
主要解決的三種異常: 
新增異常 Insert Anomaly	無法單獨新增資料
刪除異常 Delete Anomaly	無法刪除單獨資訊，會連其他想保留的資訊一併刪除
更新異常 Update Anomaly	同一資料重複存在多處，更新時可能改不完全
---
1NF 第一正規化: 欄位原子性，一格一值，消除重複群組。

考試關鍵字:
1NF 不是主要消除資料列重複。
1NF 主要是消除「一格多值」或「重複欄位」。
---
2NF 第二正規化
先符合 1NF。
非主鍵欄位必須完全依賴整個主鍵。
不能只依賴組合主鍵的一部分。

關鍵字:消除部分相依
---
3NF 第三正規化
先符合 2NF。
非主鍵欄位不可依賴其他非主鍵欄位。

關鍵字: 消除傳遞相依

例如: 
customer_id → city_id
city_id → city_name
所以 customer_id → city_id → city_name
---
BCNF: 每一個決定其他欄位的欄位，都必須是候選鍵。
關鍵字: 決定者必須是候選鍵


鍵 Key 具備 識別資料、建立關聯、限制資料唯一性的欄位 或 欄位組合，就是 KEY
候選鍵 Candidate Key 是： 可以唯一識別一筆資料，而且沒有多餘欄位的欄位或欄位組合。
主鍵 Primary Key 是： 從候選鍵中選出來，作為資料表主要識別資料的鍵。
組合主鍵 Composite Primary Key 是： 用兩個或兩個以上欄位合起來，當作主鍵。(單一欄位不夠唯一，所以要多個欄位合起來才唯一。)



名稱	中文	重點
