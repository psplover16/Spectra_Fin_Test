### 一、

#### 題目

一、用戶回報網路有「偶發高延遲」現象,網路管理員使用traceroute 指令觀察到中間節點回應波
動輿路徑跳數不穩,請以TTL 回應與非對稱路由概念診斷,試回答下列問題:(3 題,共25
分)
(1)TTL/ICMP 在路徑追蹤扮演何種角色?(5 分)
(2)非對稱路徑可能出現的原因為何?(10 分)
(3)請就以下5 種測試矩陣维度:協定/埠號、封包大小、時間、路徑、觀察邊界設備,排查該
現象(包含從遠端测回)?(10 分)

#### 擬答

(1)TTL/ICMP 在路徑追蹤扮演何種角色?
(1)基本原理說明
(a)TTL(Time To Live)用途:TTL 是IP 封包中的欄位,用來限制封包可經過的最大路由
跳數。每經過一個路由器,TTL 值會減1,當TTL 減至0 時,該路由器丟棄封包並回傳
ICMP「Time Exceeded」訊息。
(b)ICMP(Internet Control Message Protocol)用途:ICMP用於傳遞網路診斷資訊,traceroute
即利用路由器回傳的ICMP 訊息來標記每一跳的IP 與延遲時間。
(2)在traceroute 中的角色
(a)TTL 控制跳數:traceroute 會依序發送TTL=1、2、3...的封包,逐步探查沿途的每一個路
由節點。
(b)ICMP 回應標示路徑:每一跳的路由器在TTL 到期時回傳ICMP,traceroute 依此紀錄節
點IP 與延遲時間,形成路由圖。
(2)非對稱路徑可能出現的原因為何?
(1)網路設計與路由策略因素
(a)不同ISP 或自治系統(AS)間的政策路由:進出路徑可能受BGP 政策或負載分攤策略影
響,導致回程路徑與出程不同。
(b)負載平衡(Load Balancing)或多重路由(ECMP):路由器可能根據雜湊運算在多條鏈
路間分配流量,使同一目的地的封包走不同實體路徑。

(2)實體與網路環境因素
(a)鏈路壅塞或臨時故障繞路:某段鏈路延遲上升時,動態路由協定(如OSPF、BGP)可能
改變路徑。
(b)NAT、防火牆或MPLS 網段遮蔽:導致回應封包被轉送到不同的邏輯出口路徑,使觀察
結果非對稱。
(3)以測試矩陣維度排查「偶發高延遲」現象
(1)協定/埠號維度
(a)測試不同協定(ICMP、TCP、UDP)之traceroute,比較延遲分佈差異。
(b)嘗試指定應用埠號(如TCP80、443)檢查防火牆或QoS是否針對特定埠號有不同處理。
(2)封包大小維度
(a)調整封包大小(例如64、512、1500bytes),觀察延遲是否與MTU 或分片有關。
(b)若較大封包延遲升高,可能涉及路由設備緩衝或鏈路壅塞問題。
(3)時間維度
(a)在不同時段(尖峰/離峰)重複測試,確認是否為流量壅塞引起。
(b)長期記錄RTT(Round Trip Time)趨勢,以判斷問題為周期性或隨機事件。
(4)路徑維度
(a)比對雙向traceroute(從本地到遠端、從遠端回測本地),確認是否存在非對稱路徑。
(b)使用多來源測點(如不同地區或ISP)交叉驗證是否僅特定路段出現異常。
(5)觀察邊界設備維度
(a)檢查邊界防火牆、NAT、負載平衡器之CPU 使用率與流量統計。
(b)檢查是否有QoS、ACL、或安全策略導致特定流量被延遲或丟棄。
綜合診斷結論
(1)偶發高延遲與路由跳數不穩,多半與「中途節點延遲波動」或「非對稱回程路徑」有關。
(2)應透過雙向traceroute 與多維度測試矩陣交叉分析,確認是否為ISP 路由調整或邊界設備策略
造成。

### 二、

#### 題目

二、請以企業域名(Domain Name)解析的角度,說明DoH/DoT 與DNSSEC 在資安功能上如何互
補?(15 分)

#### 擬答

(1)DoH/DoT 的安全功能
(1)基本概念

(a)DoH(DNS over HTTPS):透過HTTPS 將DNS 查詢封裝於加密的HTTP 通訊中。
(b)DoT(DNS over TLS):使用TLS 進行DNS 查詢傳輸加密,確保通訊保密。
(2)資安功能
(a)防竄改與監聽:加密查詢內容,防止中間人攻擊與DNS 查詢外洩。
(b)隱私保護:避免第三方或ISP 偵測使用者查詢的網域名稱,提升隱私性。
(2)DNSSEC 的安全功能
(1)基本概念
(a)DNSSEC(Domain Name System Security Extensions)為DNS 的安全擴充協定。
(b)透過數位簽章機制,確保DNS 回應資料的真實性與完整性。
(2)資安功能
(a)防止偽造回應:以公開金鑰驗證機制,避免遭DNS 偽造或快取汙染。
(b)確保資料完整性:驗證回應資料未被篡改或替換。
(3)兩者互補之關係
(1)互補原理
(a)DoH/DoT 著重「傳輸過程安全」:確保查詢在網路傳輸中被加密,防竄改、防竊聽。
(b)DNSSEC 著重「資料來源真實性」:保證查詢結果的正確與可信。
(2)整合效果
(a)雙層防護機制:DoH/DoT 保護傳輸通道安全,DNSSEC 驗證資料內容正確。
(b)端到端安全信任鏈:查詢過程與最終解析結果皆受保護,提升整體DNS 安全性與信任度。

### 三、

#### 題目

三、請就以下10 種面向:位址長度、位址型態、位址派發、標頭(Header)大小、鄰居探索、分
片(Fragmentation)、QoS 標記欄位、總長度欄位、DNS 解析、行動(Mobility)路由模式,
比較IPv6 及IPv4 之異同。(10 分)

#### 擬答

(1)位址長度
(1)IPv4
(a)位址長度為32 位元,以十進位點分格式(如192.168.0.1)表示。
(b)可用位址約43 億個,已接近耗盡。
(2)IPv6
(a)位址長度為128 位元,以十六進位冒號分隔格式(如2001:0db8::1)表示。
(b)位址空間極大,可滿足全球長期需求。

(2)位址型態
(1)IPv4
(a)支援單播(Unicast)、廣播(Broadcast)與多播(Multicast)。
(b)廣播常造成網路負擔。
(2)IPv6
(a)支援單播(Unicast)、任播(Anycast)與多播(Multicast)。
(b)廢除廣播機制,以多播與任播取代,提升效率。
(3)位址派發
(1)IPv4
(a)可手動設定或透過DHCPv4 自動派發。
(b)須依賴NAT 延伸可用位址。
(2)IPv6
(a)支援SLAAC(Stateless Address Autoconfiguration)自動組態與DHCPv6 管理配置。
(b)不需NAT,即可提供全球唯一位址。
(4)標頭(Header)大小
(1)IPv4
(a)基本標頭長度20 位元組,可變長度(含選項欄位)。
(b)結構複雜,處理效能較低。
(2)IPv6
(a)固定標頭長度40 位元組,無選項欄位,僅以延伸標頭方式附加。
(b)結構簡化,有利硬體快速轉送。
(5)鄰居探索(Neighbor Discovery)
(1)IPv4
(a)依賴ARP(Address Resolution Protocol)解析MAC 位址。
(b)ARP 廣播可能導致網路負載。
(2)IPv6
(a)使用ICMPv6 ND(Neighbor Discovery)協定,以多播取代ARP。
(b)同時可支援自動位址設定與重複位址偵測。
(6)分片(Fragmentation)
(1)IPv4
(a)主機與路由器皆可執行分片。
(b)多次分片與重組會造成效能損耗。
(2)IPv6
(a)僅來源端主機可分片,路由器不再分片。
(b)透過Path MTU Discovery 動態調整封包大小。
(7)QoS 標記欄位
(1)IPv4
(a)於標頭中設有TOS(Type of Service)欄位,用於服務品質標示。
(b)實際應用有限。
(2)IPv6
(a)以Traffic Class 與Flow Label 欄位明確支援QoS。
(b)可建立流量辨識與優先權管理。

(8)總長度欄位
(1)IPv4
(a)含有Total Length 欄位,用以表示整個封包長度(含標頭與資料)。
(b)可變長封包結構。
(2)IPv6
(a)改用Payload Length 欄位,僅計算資料負載長度,不含標頭。
(b)封包結構更為簡潔與固定。
(9)DNS 解析
(1)IPv4
(a)DNS 使用A 紀錄對應IPv4 位址。
(b)適用於傳統網路環境。
(2)IPv6
(a)DNS 使用AAAA 紀錄對應IPv6 位址。
(b)DNS 可同時支援雙棧(Dual Stack)解析。
(10)行動(Mobility)路由模式
(1)IPv4
(a)需使用Mobile IPv4 進行行動支援,結構較複雜。
(b)透過Home Agent 與Care-of Address 轉送封包。
(2)IPv6
(a)原生支援Mobile IPv6,路由效率更高。
(b)不需三角路由(Triangle Routing),可直接與對端節點通信。

### 四、

#### 題目

四、定義「快樂數」為一個正整數N 經過以下過程:
(1)將N 的每一位數字平方後相加,得到新數字。例如:25→2x2+5x5=29
(2)重複此步驟,直到出現下述其中一種結果:
-得到1,則N 是快樂數
-進入循環(例如:4→16→37→58→89→145→42→20→4),則N 非屬快樂數
請設計一函式isHappy(int n),並註明所使用的程式語言:(15 分)
輸入:正整數 n (1 <= n <= 10^9)
輸出:若n 是快樂數,回傳true;否則回傳false

#### 擬答

本題使用 C++ 來撰寫,程式碼如下:

```cpp
bool isHappy(int n) {
    int used[1000] = {0};  // 記錄出現過的數，避免重複

    while (true) {
        int sum = 0;
        int temp = n;

        while (temp > 0) {  // 計算每位數平方和
            int d = temp % 10;
            sum += d * d;
            temp /= 10;
        }

        n = sum;  // 更新 n
        if (n == 1)  // 如果變成 1：快樂數
            return true;

        if (used[n])  // 如果重複出現進入循環：非快樂數
            return false;

        used[n] = 1;  // 記錄這個數出現過
    }
}
```

### 五、

#### 題目

五、Java 是一種常見的物件導向程式語言,請回答下列問題:(3 題,共20 分)
(1)Java 中基本型別(Primitive Type)與参考型別(Reference Type)差異為何?(5 分)
(2)Java 的垃圾回收機制(Garbage Collection)如何運作(3 分)?何時觸發(3 分)?
(3)Java 物作導向的三大特性為封裝、繼承、多型,請分別說明其定義奥如何在Java 中實現。
(9 分)

#### 擬答

(1)Java 基本型別
(1)byte, int, long, float, double, char, boolean
(2)儲存的是實際的值,例如 int n = 5,存放在stack 記憶體,存取速度快。
(3)不具備方法,無法直接呼叫成員函式。
Java 參考型別
(1)類別、介面、陣列、List、字串等,儲存的是物件的記憶體位址參照,而非物件本身。
(2)存放在heap 記憶體,由 JVM 管理。
(3)可呼叫方法,例如 String s = "abcd"; 透過length()方法。

(2)垃圾回收機制
Java 使用Garbage Collector (GC)來管理記憶體。當物件不再有任何變數或參照時,GC 會將它
視為垃圾,釋放佔用的堆記憶體。
觸發時機
當記憶體不足時,JVM 會自動觸發GC。也可能在系統空閒時執行,來回收未使用的物件。
程式設計師可呼叫System.gc()讓JVM 執行,但不保證會立即執行,要看JVM 的排程。
(3)封裝:將資料與方法包裝在類別中,限制外部存取,透過getter/setter 來存取。
使用:public、private、protected。
Ex:
class Person {
private String name;
public String getName() { return name; }
public void setName(String n) { name = n; }
}

繼承:子類別可以繼承父類別的屬性與方法,達到程式碼重用。
Ex:
class Animal {
void eat() { System.out.println("eat"); }
}
class Bird extends Animal {
void move() { System.out.println("fly"); }
}

多型:同一個方法在不同物件中有不同的呈現方式。可分為:多載與覆寫。
多載(Overloading):方法名稱相同,但是參數的型態或是個數不同。
覆寫(Overriding):子類別重新定義父類別的方法。

### 六、

#### 題目

六、請說明下列網站攻擊的行為原理及如何防禦:(3 題,每題5 分,共15 分)
(1)SQL Injection
(2)Cross-Site Scripting, XSS
(3)CSRF

#### 擬答

(1)SQL Injection—行為原理與防禦
(1)行為原理
(a)攻擊方式:攻擊者將惡意SQL 片段注入應用程式輸入欄位或參數,使後端資料庫執行非
預期查詢(如串接未過濾的字串到SQL)。
(b)類型與影響:in-band(錯誤/聯合)、blind(布林/延時)、out-of-band;可能導致資料外
洩、資料竄改、驗證繞過或完全系統入侵。
(2)防禦措施
(a)預防(首要):使用參數化查詢 / prepared statements 或ORM,避免字串拼接;對所有
輸入做型別與範圍驗證。
(b)補強:採用最小權限資料庫帳號、嚴格錯誤處理/屏蔽資料庫錯誤資訊、WAF 規則、定
期程式碼掃描與滲透測試、異常查詢監控與告警。
(2)Cross-Site Scripting (XSS) — 行為原理與防禦
(1)行為原理
(a)攻擊方式:攻擊者把惡意腳本(通常是JavaScript)注入到網頁內容,當其他使用者載入
該頁面時腳本在受害者瀏覽器執行。
(b)類型與影響:reflected(回射)、stored(儲存型)、DOM-based;影響包括竊取cookie、
會話劫持、鍵盤或畫面劫錄、偽造操作。
(2)防禦措施
(a)預防(首要):對輸出做上下文相關的編碼/escape(HTML、Attribute、JavaScript、
URL);優先在輸出端編碼而非僅在輸入端過濾。
(b)補強:使用安全的模板引擎、Content Security Policy (CSP)限制可執行來源、將session
cookie 設HttpOnly 與SameSite、避免在DOM 中直接插入未編碼的HTML、定期掃描與
安全測試。
(3)Cross-Site Request Forgery (CSRF) — 行為原理與防禦
(1)行為原理
(a)攻擊方式:攻擊者誘導已登入之使用者在受信任站點上發送未授權的狀態改變請求(例
如透過表單、自動GET/POST、圖片請求),瀏覽器會自動攜帶cookie 或認證資訊。
(b)影響:在使用者權限下執行未經授權操作(如變更密碼、轉帳、刪除資料)。
(2)防禦措施
(a)預防(首要):對所有會改變狀態的請求使用不可預測的Anti-CSRF token(伺服器端驗
證token)或採用double-submit cookie 技術。
(b)補強:設定cookie 的SameSite=Lax/Strict、對敏感操作要求額外驗證(re-auth / MFA)、
驗證Origin/Referer 標頭(僅在可信來源允許)、避免使用GET 做會改變狀態之操作。
